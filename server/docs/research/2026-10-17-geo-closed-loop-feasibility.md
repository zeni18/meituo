# GEO 品牌优化闭环可行性调研

调研日期：2026-10-17。范围为产品和技术可行性核对；未启用供应商、创建收费任务、订阅监测或执行对外发布。

## 结论

建议采用“品牌建档 → 确认检测问题 → 基线诊断 → 优化计划草稿 → 用户修改/确认 → 执行 → 周期复测 → 复盘调整”的主流程。当前代码已有品牌/事实/问题/文章/生成任务/媒体订单/消费单，具备执行侧基础；核心新增工作是真实监测接入、项目及计划版本、审批和执行关联、定时复测与报告。

产品流程可实现，不代表能保证某次发稿后被 AI 推荐。诊断结果应来自指定平台、端、地区、模式和时间下的实际采样；计划中的原因分析和预期收益需标注推断及验证方式。

## 官方资料核对

- [Peec Actions](https://peec.ai/product-actions)：依据可见度和竞品来源差距生成有优先级的优化建议；区分自有页面和站外内容行动。
- [Peec 2026-10-13 更新](https://peec.ai/changelog)：建议带证据，可编辑、拒绝或接受改动；强调由用户批准执行。这支持“诊断—计划—确认”的交互方向。
- [AIDSO 官网](https://www.aidso.com/)及[监测功能说明](https://www.aidso.com/article/details/aisou-geo-monitoring-data-platform-core-features-NdtJVZ5Y.html)：供应商自述支持国内多平台品牌诊断、来源追踪及持续监测。覆盖和准确性仍需样本验收；官网产品能力说明不能替代商务 API 契约。
- [AIDSO API Key 页面](https://geo.aidso.com/setting?type=apiKeyManage)为动态页面，本轮公开读取未取得可验证的端点、鉴权、计量和回执协议，因此国内监测暂不能认定为已完成接口选型。
- [DataForSEO Scraper 与 Responses 区别](https://dataforseo.com/help-center/what-is-llm-scraper-api-and-what-data-does-it-provide)：普通模型 API 输出与消费端网页界面采集具有不同用途。[Scraper 文档](https://docs.dataforseo.com/v3/ai_optimization-llm_scraper-overview/)当前列明 ChatGPT、Gemini，不能直接充当豆包/元宝等国内平台监测来源。
- [Google AI 搜索官方指南](https://developers.google.com/search/docs/appearance/ai-features)：可抓取、可靠内容、清晰文本和一致的结构化信息仍重要，符合要求也不保证抓取、收录或展示。该结论适用于 Google，不能直接推定所有国内 AI 平台使用相同规则。

## 推荐业务流程

| 阶段 | 用户操作与系统产物 | 必要约束 |
| --- | --- | --- |
| 品牌建档 | 品牌主名/别名、官网和门店、服务地区、产品、目标客群、可证明卖点、资质/案例、竞品 | 信息需带来源和有效期；资料完整度与 AI 可见度分开 |
| 检测范围确认 | 根据品牌信息生成真实客户问题，用户删除/新增/调整；确认平台、地区、端、联网/思考模式 | 品牌词、品类词、场景词、对比词分组；固定核心问题版本 |
| 基线诊断 | 采集回答原文、可提供的引用链接/截图、时间和环境；识别本品牌/竞品及事实错误 | 品牌档案用于规划问题和核对事实，不能注入受测对话来制造提及；模型 API 自测单独标注 |
| 优化计划草稿 | 将具体差距转换为任务、优先级、依据、内容主题、目标渠道、负责人、期限、预计消耗、复测规则 | 每条任务链接诊断证据；区分观察事实与原因假设；只使用已授权可执行能力 |
| 修改和确认 | 用户修改计划、删任务、改预算和节奏；确认形成版本快照 | 未确认不得执行；增加付费发布、扩大预算/渠道或改变目标需再次确认 |
| 执行 | 关联原生成任务、文章审核、已授权发布流程和订单回链 | 内容待审核、发布中、已发布、待复测、已验证分别记录，不能仅凭“已发布”宣告有效 |
| 复测与反馈 | 相同核心问题和环境重复采样，与基线/上周期对比；生成阶段报告和调整建议 | 数据不足显示待观察；失败与超时单列；更换问题或平台后不混算历史趋势 |

## 诊断和指标口径

1. 品牌问题（例如“某品牌有哪些服务”）衡量信息正确性；非品牌问题（例如“某地区如何选择某类服务”）衡量自然发现。两类分别展示，避免带品牌名的问题抬高曝光指标。
2. 品牌提及率：有效回答中出现已核验品牌实体的样本比例。名称歧义、别名和同名竞品需要实体匹配和人工纠错。
3. 推荐表现：只有真正列入推荐选项时才计入；普通顺带提及不等于推荐。只在明确列表中记录位置，不把所有自然语言回答强行转成排名。
4. 来源引用率：回答明确引用本品牌官网或可归属内容 URL 的样本比例。抓取记录、被检索、被引用和品牌被提及分别存储。
5. 信息正确性：对已批准事实进行核验，保留错误片段、核验来源和人工修正。
6. 执行进度：完成任务/总任务、已审核文章、真实发稿回链、失败/阻塞和消耗。
7. 业务结果：有网站统计或线索来源数据后再展示访问、咨询与转化。检测提及率不是全网真实曝光量；同期改善也不能直接证明由某篇文章造成。

采样建议（产品默认值设想，非行业标准）：先选 20—30 个问题、约 3 个实际可用平台，每个组合重复 3 次。例如 30 × 3 × 3 = 270 个样本/完整周期。重复样本不能自动视作完全独立，需展示样本量和采样条件。首轮作为基线，之后周级复测，观察多个周期；没有固定的保证见效天数。

## 优化计划内容

计划应覆盖企业信息纠错、官网/知识页面补全、客户问题内容创作、合适的第三方来源建设及复测任务。海讯社承担有对应资源的媒体采购发布，不能代替诊断，也不能承担所有官网/CMS、账号授权和社区运营行动。

示例：同一组问题中竞品多次被推荐，本品牌未提及；来源里有行业比较页，本品牌缺少相应场景说明。系统可建议补充有证据的场景页/FAQ、制作相关文章，并从实际可用媒体里筛选相关渠道；这些动作有待复测的效果假设，不应承诺“发布几篇就进入前几名”。

## 当前系统能力与缺口

| 能力 | 代码现状 | 后续工作 |
| --- | --- | --- |
| 品牌与事实库 | 已有持久化和隔离接口 | 增加品牌别名、竞品、资料核验、服务范围及版本关联 |
| AI创作和资料整理 | 已有队列、模型能力配置、消费流水关联 | 由计划任务带入内容要求、证据及验收目标；实际使用须有可用配置 |
| 媒体发布 | 已有海讯社选媒体/报价/订单/回链流程 | 将文章、媒体订单与项目任务关联；正式发布仍依赖通道开通 |
| 国内AI可见度 | `GeoConnections.visibility_cn.ready=false`，诊断界面禁用执行 | 获取正式供应商契约、验证端侧结果、按原市场接入计量 |
| 计划草稿与确认 | 当前无独立计划版本和审批流程 | 新增项目、计划版本、确认记录、行动任务及依赖关系 |
| 周期复测与报告 | 现有队列不是周期监测服务；业务报表不等于效果报表 | 增加受预算约束的定时任务、采样批次、基线比较和站内报告 |

## 权限、计费及交付顺序

- 保持平台/OEM/获授权代理配置供应商；OEM 可逐能力借用平台，商家不获得上级 Key。
- 商家确认自己的项目计划，代理在已授权服务范围内协作；按项目归属和当前层级查询，报告导出/通知同样验证归属。
- 不新增 GEO 独立计费体系。手工资料和计划编辑不扣费；AI 分析、监测与发布等实际消耗沿用平台已有市场和流水。订阅时确认频率、数量和预算上限，未配置合法价格或授权不得调用。
- 建议第一阶段交付品牌向导、问题集、带来源诊断（供应商未就绪时仅人工采样）、可编辑计划及确认记录。
- 第二阶段接入真实国内监测，打通计划任务—内容—媒体订单—复测证据的关联，形成可验收的完整周期。
- 第三阶段增加周期复测、站内周报、异常提醒和月度复盘。建议进展实时更新、周级效果报告；具体频率按成本和数据稳定性配置，此文没有实际创建任何自动通知。

四个现有板块可以保持：工作台承载项目流程和待办，AI创作素材库承载品牌资料和内容任务，媒体发布承载执行回执，数据中心承载基线/复测/阶段报告。应优先补齐闭环，再扩展非核心工具入口。
