# 本地商家入口与 OEM 管理

基于公开版 1.0.399，原 AI 前台直接作为商家后台。没有增加独立商家工作台；登录成功进入 `/ai/tools`，保留原有菜单、工具、品牌和版权信息。

## 本地访问

- 商家登录：`http://localhost:8090/login`，账号 `demo2026`。
- OEM 管理：`http://localhost:8090/admin/`，账号 `admin`。
- 平台管理：`http://127.0.0.1:8090/platform/`，账号 `admin`。
- 总后台代理列表：`http://127.0.0.1:8090/platform/tenant/lists`。原“租户管理 → 租户列表”现为“代理管理 → 代理列表”，原租户按 OEM 类型展示。
- 本地体验密码：`AigcLocal2026!`。
- OEM、一级代理和二级代理统一入口：`http://localhost:8090/admin/login`。OEM 账号 `admin`；本地体验代理账号 `agentdemo2026`，密码同上。体验代理已分配“代理体验商家”（登录账号 `agentmerchant2026`），原 `demo2026` 商家保持 OEM 直属。旧 `/agent` 和 `/agent/login` 入口跳转到统一登录页。
- 启动：在项目目录执行 `powershell -File scripts/local-start.ps1`。

MariaDB 11.4.5 使用独立回环端口 3307、数据库 `aigc_local`；PHP 使用回环端口 8090。环境密码保存在忽略的 `.env` 和本机运行目录，不提交到源码仓库。

## 已实现

- 服务端拦截未登录的前台页面；工具目录和功能接口也需要有效商家登录。
- 使用原用户账号和会话，登录后直接进入原 AI 工具后台。原后台退出登录后返回登录页；失效、伪造和被停用的凭证不能继续调用接口。
- OEM 用户列表改为商家管理，可创建、编辑、停用商家，管理联系人、行业、代理归属；原账号、余额、资产和任务归属保留。
- OEM 代理管理支持一级、二级代理及联系人、状态、备注。代理数据按 OEM 隔离。
- OEM 新增代理需设置登录账号和初始密码；编辑时可开通原有代理的登录账号或重置密码，密码留空则保留当前密码。账号唯一范围为所属 OEM，管理员与代理账号不能重名。
- 一级代理后台提供“商家管理”和“代理管理 → 代理列表”。可开通自己名下二级代理的登录账号、编辑资料、重置密码、启用或停用；级别和上级由服务端自动绑定，不能开通一级或三级代理、修改他人代理、跨 OEM 或转移上下级关系。
- 一级代理可管理直属和其名下二级代理商家，二级代理仅可管理直属商家；不能查看其他代理、OEM 直属或其他渠道商家的名单、统计、搜索结果，也不能通过伪造 ID 修改或转移它们。二级代理没有代理管理菜单，相关列表和写入接口均拒绝访问。
- 代理可在授权范围内创建商家、编辑资料、停用账号、调整所属代理；一级代理的可选归属仅限自己及名下二级代理。二级代理的商家归属仅限自己，不能建立下级代理；所有代理均不能进入 OEM 或平台管理接口。
- 三种身份共用原管理端的登录页、后台框架和 `/tenantapi/login/account` 登录接口，按账号识别身份。代理复用原管理端 Token 传递方式，使用 `agent_` 命名空间和服务端摘要会话；数据库只存会话摘要和密码哈希。停用代理、停用其上级或重置密码会撤销相关会话；重新启用不会恢复旧会话。代理关系变化后服务端即时重新计算访问范围。
- 代理身份由全局 `AgentAdminMiddleware` 先验证，放行本人资料、身份菜单、受限商家读写、代理经营功能和退出接口；仅一级代理额外放行受限二级代理列表、写入与额度划拨接口。二级代理列表、统计、搜索、分页和可选项在数据库查询中同时限定本 OEM、当前上级和二级级别，编辑时加锁验证归属。任何其他原后台路径都拒绝，不能依赖原系统对未注册菜单接口的默认放行规则。OEM 使用原后台身份和权限逻辑。
- 新建商家同时创建真实原系统账号，初始余额为零；停用商家撤销已有会话。
- 侧栏、账户菜单和商家资料页读取 OEM 商家名称；“个人资料”“昵称”入口改为“商家资料”“商家名称”。通过资料页修改名称会同步保存到 OEM 商家档案，登录账号与资产归属不变。
- 管理接口检查员工菜单权限、OEM 数据范围和代理层级。
- 总后台统一列出 OEM、一级代理和二级代理，支持类型、所属 OEM、状态和账号关键词筛选；可开通或编辑三种账号。一级代理必须归属有效 OEM，二级代理必须选择同一 OEM 下有效的一级代理。
- 总后台工作台入口改为“代理管理”，代理总数包含 OEM 与两级代理，商家总数取实际商家档案；OEM 算力余额继续使用原余额数据。
- 总后台开通 OEM 沿用原始完整初始化流程，创建管理账号、域名、菜单、支付/短信配置、装修和默认应用；初始算力余额不额外赠送。新 OEM 使用共享数据表模式，可设置 1–3650 天有效期。
- 总后台编辑 OEM 保留现有域名和服务配置；可调整名称、电话、状态和管理账号、重置密码。关闭 OEM 会撤销其相关管理与代理会话。OEM 有效期续期继续使用原 OEM 套餐模块。

## 代理经营功能

- 工作台：`/admin/agent-workbench`，显示权限范围内商家总数、今日新增、7 天内到期提醒、今日消耗算力、订单与真实线上支付金额、手工办理未登记收款金额及本人可分配额度。
- 商家服务 → 商家套餐：`/admin/agent-services/packages`。使用本 OEM 上架套餐，开通/更换从今日计时，同套餐续费从未到期日延长；原免费会员保持长期有效。真实更新 `user_membership` 权益，赠送点数扣减办理代理额度，额度不足则连同权益更新全部回滚。保留商家已有应用限制，套餐升级不会静默扩大特意收窄的白名单。
- 商家服务 → 应用授权：`/admin/agent-services/apps`。只能选择 OEM 有效应用及商家当前套餐允许的范围；未勾选应用在实际 API 执行、会员访问检查和前端应用权限清单中均被拒绝。OEM 取消应用后，既有商家白名单不能绕过；未设置白名单的历史商家保留原有权限逻辑。基础系统 `system_default` 不受业务应用白名单影响。
- 算力管理 → 商家充值：`/admin/agent-power/recharge`。从办理代理自己的可分配额度扣减、增加真实商家余额、写原商家算力流水及经营订单；一级代理可操作直属及名下二级代理商家，二级代理仅自己。输入金额为登记应收，不自动确认现金收款。
- 算力管理 → 商家算力流水：`/admin/agent-power/ledger`，查询所属商家所有算力增减，支持商家关键词、来源单号、日期、分页与对应统计；分表 OEM 的账户与流水读取/写入正确的独立表。
- 算力管理 → 我的额度流水：`/admin/agent-power/quota`，每个代理只查询自己的额度余额、OEM 授额、上下级划拨和商家充值/套餐赠送扣减流水。不能指定其他代理钱包。
- 订单记录：`/admin/agent-orders`，汇总当前所属商家的原会员订单、原充值订单及代理手工办理记录，支持关键词、收款状态、日期和分页。手工办理显示“已办理 / 未登记收款”，不创建虚假已支付订单；线上订单沿用原支付/退款状态；已支付金额按累计支付口径展示，不作为扣除退款后的净收入，退款情况需按订单状态核对。商家或代理迁移后，历史订单、流水和汇总也按当前归属重新校验。
- OEM 主账号在“代理管理”列表使用“授予额度”；一级代理在自己的“代理列表”使用“划拨额度”。初始额度为零。额度是 OEM 授予代理可分配的零售点数额度，不是现金，不扣减用于模型成本计费的上游 OEM 算力余额；一级向二级划拨必须扣减自己的额度，双方合计不变。普通 OEM 员工及二级代理不能发行额度。
- 所有经营写入检查 POST、同源和当前有效身份，使用事务、行锁、请求幂等键和负余额校验。相同请求重复或并发提交只办理一次；相同幂等键携带不同内容会被拒绝。审计记录保留经办、目标、原始金额/算力、权益快照、备注及请求摘要。

暂未实现佣金、结算、在线收款的新通道或自动确认线下收款。未调用收费 AI 生成接口；原系统全部生成能力未逐项验收。
