# 项目约定（给 AI 助手和开发者）

## 商家端界面

- 任何商家端页面（`/ai/*`、`public/merchant/*`）的新增或修改，必须先读 `docs/商家后台改版规范.md` 中与当前任务相关的章节，并按其中的 Token、卡片等级、页面骨架实现；不要全文加载长规范。
- 交付前按规范中与当前任务相关的禁止项逐条自查，并在浏览器里实际打开页面检查。
- 只维护浅色主题。颜色、圆角、阴影只用 `--ui-*` 变量，不写死新的颜色。
- 计费单位一律叫 TP，金额用 `\uE000` + 数字显示，不写“算力”“积分”。
- 新增侧栏入口只在 `public/merchant/nav-v2.js` 的 `GROUPS` 里登记。
- 短剧/漫剧、无限画布不套用商家端风格。

## 设计出发点（用户 2026-10-21 明确要求）

- 先从用户要完成的事和最短路径出发，再谈好看。每页先写“用户要完成什么”，再排版。
- 参考稿要先质疑取舍，不能照着复刻。
- 每页先定一个主角（例如视频剪辑的预览），其余安静退后。
- 不用“线型图标 + 浅色底框”，图标统一实心。
- 卡片背景不做纯色，用渐变、层次、多层阴影等材质，且放在规范规定的位置。
- 功能盘点、砍并清单要逐项完整，不图省事。
- 交付前必须真实渲染出来看（浏览器或无头浏览器截图），不能只看代码。

## 改动安全

- `public/merchant/` 已纳入 Git；改动现有文件前仍须备份到本机忽略目录 `.collab/local/ui-v2-backup/<时间>/`。


## GitHub 同步

- 用户在开工前让当前 AI 拉取 GitHub 最新代码，完工后让当前 AI 提交并推送。按用户当次指令执行，在当前分支同步，不按 AI 或机器分配文件、职责或审批权限。
- 拉取前检查并保留本地修改，使用 `pull --ff-only`；遇到分支分歧先比较，不覆盖、不强推。完成后只提交本次任务文件，运行适当检查，再推送 GitHub。
- `.env`、数据库、会话、上传素材、API 密钥及本机运行目录不进 Git；数据库结构变更使用迁移文件，两台不共用开发库。
- 环境搭建与同步命令见 `.collab/README.md`。交付说明改动、验证结果和未完成事项。
