# 品牌列表与企业知识中心

用户确认：一个品牌可有多个门店，企业知识库属于品牌。原门店入口升级为品牌卡片列表；详情包含数据概览、企业知识库、旗下门店。门店卡片进入详情后管理资料、员工、装修、续期及码牌申请。

视觉沿用商家主题，以紫色品牌名片、真实统计、文章时间统计、平台真实采样分布和内容列表呼应用户参考图。无自动样本时明确为空，不伪造收录量、排名或关键词热度。页面不增加重复的标题横幅，适配深浅主题与移动屏幕。

新品牌表保存商家与品牌归属、联系方式、标识和知识；门店关联表保证一家门店属于一个品牌。现有门店 ID 不变，默认品牌保留历史 GEO 范围零及原企业资料；其他品牌使用独立范围。GEO 资料、文章、任务、诊断项目、发稿草稿与订单按品牌过滤。后台文本任务、监测回执、定期复测和进度报告从其原始任务/项目恢复范围，计费与平台/OEM/代理权限不变。

执行 `php scripts/install-merchant-brands.php` 建立品牌与门店关联、给 GEO 根记录和发稿表补充范围字段，并幂等归集现有数据。不得仅发布前端或只执行建表 SQL，需执行安装脚本。未删除历史资料。

旧 `/ai/stores` 路径继续使用，侧栏名称改为品牌列表。旧门店保存接口自动归入现有默认品牌；显式转移门店保留员工、装修和原始 ID。回收品牌要求无在用门店、无执行中任务，并停用未来定期复测；恢复后保留知识与历史记录，不自动恢复付费计划。

验证结果：

- `merchant-brands.http.php`：60 项，包含多品牌、多商家、原资料迁移、知识库双向同步、乐观锁、门店归属与转移、旧接口、关联记录隔离、发稿草稿、回收恢复、停止复测及原钱包不扣费。
- 原门店 HTTP 80 项、GEO 资料 HTTP 68 项、工作流 HTTP 74 项、概览 HTTP 22 项通过。
- 自动诊断离线集成 77 项通过；`GEO_BRAND_SCOPE_QA=1` 的第二品牌运行 79 项通过，验证后台回执、账单、封存报告与定期复测恢复原始品牌。
- 独立 GEO 集成 54 项、海讯社集成 84 项、发稿 HTTP 49 项、导航合约和主题同步合约通过。独立 GEO 集成首次并发执行时发生事务保存点错误，单独复跑通过；未修改其原测试。
- TypeScript 与 Vite 构建、修改的 PHP/JS 语法及差异检查通过；差异检查仅有仓库原有 `.gitignore` 换行提示。
- 浏览器核对卡片、商户详情、品牌知识库与 GEO 往返、深色表单和弹窗。390px 实际页面 iframe 内容宽度与滚动宽度一致，无横向溢出；主题恢复为原来的跟随系统。验收表单均取消，未覆盖真实品牌事实。

截图在 `runtime/local/evidence/brand-overview-light.png`、`brand-overview-dark.png`、`brand-overview-mobile-dark.png`、`brand-dialog-dark.png`、`brand-list-light.png`。验收只使用独立测试记录和模拟供应商，未进行外部付费调用。本地 GEO 后台进程已在无待执行任务时重启以加载新品牌上下文；平台/OEM 供应商开关保持原状。
