# 自动化计划

入口：侧边栏「自动化计划」，地址 `/ai/automation?tenant_id=1`。GEO 诊断范围直接在「GEO诊断 → 开始诊断」中设置，原优化项目页面已移除。

## 视频库存补充

1. 在 AI 视频剪辑中保存包含可用素材的工程，建立目标成片库。
2. 新建视频计划，选择工程、成片库，设置触发阈值、补充目标、每批数量、检查间隔和最多执行轮数。
3. 保存后为暂停状态；启用时核对执行范围与数量上限。

库存按成片库的使用次数限制统计。无限使用的库只统计尚未分配的视频；正在生成的视频计入预计余量。低于阈值时开始补充，随后分批补到目标，或在达到轮数、有效期上限时结束。每批最多 10 条、每计划最多 20 轮。

计划保存剪辑工程配置快照。云剪辑继续使用已有 OSS、视频合成服务及回调/轮询、归库流程。云服务费用由对应云账号承担，目前没有视频算力预算结算，以数量和期限限制执行。

## GEO 自动优化与发稿

1. 在「GEO诊断 → 开始诊断」保存问题和平台范围，完善企业知识库。当前自动诊断支持全国、联网搜索模式以及供应商适配器已接入的平台。
2. 新建 GEO 计划，选择范围、模型、1–5 家投稿媒体，每轮最多生成 1–3 篇文章。
3. 设置轮次间隔、发布后等待复测的天数、每轮算力预算、最多执行轮数、授权有效期；保存后启用。

每轮执行：创建独立项目 → 完整基线诊断 → 按未提及的非品牌问题生成文章 → 入文章库 → 指定媒体核价并投稿 → 等待真实发布回链 → 延迟同范围复测。上一轮完成后才计算下一轮间隔。

未发现符合条件的问题时，本轮直接结束，不创建写作和投稿任务。诊断结果不完整、稿件过短或包含待核实标记时暂停，保留原任务与结果。这是内容完整性检查，不代表自动事实核验，也不保证 AI 收录或排名。

## 预算与暂停

- 预算单位为「算力」。诊断、写作、媒体发稿、复测共同占用每轮预算；总授权上限为每轮预算 × 最多轮数。
- 诊断和投稿按现有报价占用；写作按执行模型价格、保守输入长度与 2048 token 输出上限占用。实际费用仍由原消费流水结算，预算占用不等于实际消费，保守预留不释放复用。
- 每个付费步骤在创建任务或发出模型请求前检查预算。钱包余额不足仍由原业务拦截。媒体只使用已选白名单；不自动替换，不自动为失败任务重复付费重试。
- 新轮开始前检查媒体目录报价有效性，投稿前再次核价；已下单后的回链等待及复测不受目录报价过期影响。
- 暂停停止后续步骤，已创建的剪辑、诊断、写作任务和投稿订单继续处理。恢复仍沿用原执行记录；需要核对的失败任务不会生成替代任务。
- 服务授权、账号状态、品牌资料或关键接口配置变化会阻止继续执行。未执行的暂停计划可编辑；已经执行的计划保留历史，调整范围需新建计划。

## 部署

在项目根目录执行 `php scripts/install-merchant-automation.php`，应用幂等数据库升级和前端入口路由。完整 GEO 安装脚本也包含该步骤。前端在 `frontend/geo-semi` 执行 `npm run build`，发布 `public/merchant/geo-semi` 和 loader，并更新页面缓存版本。

保持以下进程由服务器进程管理器守护：

```text
php think merchant-automation:work
php think merchant-clip:work
php think merchant-geo:work
php think media-press:work
```

新增调度进程空闲时每 5 秒扫描一次到期计划，执行中轮次通常每分钟跟进；视频空闲检查按计划间隔，GEO 新轮按计划天数。页面无需一直打开。`php think merchant-automation:work --once` 可处理一次到期计划，适合运维排查，不会启用暂停计划。

本地 `scripts/local-start.ps1` 已加入守护进程启动。服务器上线需配置自己的服务管理器开机启动，并在代码更新后平滑重启 GEO 和自动化进程。媒体报价需每日同步，可复用现有 `media-press:sync` 调度。页面显示调度心跳；它只代表调度进程存活，各业务队列的最终结果见执行记录。

启用 GEO 前需配置：诊断供应商、文本模型和计费、媒体发稿接口及本站公网预览域名；启用视频前需配置 OSS 与视频合成服务。所有计划按当前登录商家隔离。

## 验证

`php tests/automation.integration.php` 使用专用本地数据库事务和模拟供应商，验证真实队列、库存归库、基线采样、文章入库、媒体订单、延迟复测、预算拦截及重复调度。测试数据整体回滚，不调用真实付费接口。

`node tests/geo-navigation.contract.cjs` 验证独立入口、原 GEO 页面和原生路由衔接；`php tests/geo-visibility.integration.php` 验证原诊断流程回归。
