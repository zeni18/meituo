### 0.2 开工与交付流程（用户 10-23 定：先落本机，再推 GitHub）

改动必须**先出现在用户本机的 8090 上、用户能看到，再推送 GitHub**。否则用户无法在本机核对，方向会越走越歪。

1. **开工**：在本机项目目录 `git pull --ff-only`，确认工作区干净。
2. **改动前备份**要改的已有文件到 `.collab/local/ui-v2-backup/<日期-时间-页面>/`（该目录不进 Git）。
3. **改**：只用本规范的 Token、组件和骨架（第 3–11 节）。
4. **自测**：`node --check` 语法检查；在无头测试台（0.5）用 1280 / 1440 / 1920 截图，确认无横向滚动、无文字溢出、控制台无报错；主要流程走一遍（不点扣 TP / 发通知 / 对外发布的最后一步）。
5. **落到本机**：文件写进本机项目目录，刷新 `http://127.0.0.1:8090` 用真实数据检查（侧边栏浏览器或用户自己的浏览器）。
6. **给用户看**：前后对比图（1440 为主，附 1280）+ 改了什么 + 需要用户拍板的点。
7. **用户确认后再提交推送**：只 `git add` 本次任务的文件，提交说明写清楚改了什么，推送当前分支（不强推）。在 `.collab/handoffs/` 写交接，更新本规范（第 0.1、14 节和「更新记录」），并同步到 claude.ai 项目「AI营销工作台」里的同名文档。

在云端运行、改不了本机的 AI（例如 Claude 云端会话）：通过设备连接把改好的文件写进本机项目目录（第 5 步），再由本机的 AI（如 Codex）执行第 7 步提交推送，云端随后 `git pull` 对齐。不要先从云端推送、再让本机拉：本机已经有同样的改动，`git pull` 会因「本地改动会被覆盖」而中止。

### 0.6 容易踩的坑

- **svg 上色用 `color`，不用 `fill`**：`.uk svg.uk-i{fill:currentColor}` 优先级更高，页面 CSS 写 `fill` 不生效。
- **页内页签用 UK.setView(url)**（底层 RouterHistory.replace，不触发页面路由；隔离测试台回退 replaceState）。详情等确需返回的动作传 {push:true}，同步原生历史缓存、current/position，不能复制旧 history.state 或伪造 popstate。跨页面才用 UK.go，保留租户参数并走单次 SPA 导航。
- **旧页面让位**：新页面接管的地址，旧脚本挂载前要问 `window.UK_OWNS()`（`workspace.js`、`finished-library.js`、`geo-semi-loader.js` 已加）。
- **新页面脚本要在 `workspace.js` 之前注入**，否则首次加载时旧页先挂上。
- 所有接口都要带 `tenant_id`（放 query）。`workspace_asset/update` 的 body 不能带 `tenant_id`。
- **GEO 接口都要带 `brand_id`**（`GeoBrandScope` 按它定品牌）。`geo-v2.js` 的 `geo()` 已自动带上。
- 后端 `options` 返回的 `point_unit` 可能是「算力」：**界面一律显示 TP**，金额用 `UK.tp(n)`，不用接口给的单位字样。
- 会扣 TP 的提交都带 `request_key`。断网或没拿到明确答复时，重试必须沿用同一个 `request_key`，避免重复扣费；接口明确返回业务错误（`err.answered === true`）才换新 key。
- 测试里**不点**会扣 TP、发通知、对外发布的最后一步（确认生成、确认拓词、开始检索、确认诊断、派给员工、下单），走到前一步为止并告诉用户。
- 旧 GEO（`frontend/geo-semi`，React + Semi）只有构建好的 `public/merchant/geo-semi/workspace.js`。云端会话的 npm 源被代理拦截，没法重新构建，所以改 GEO 一律用 ui-kit 重做，不改 Semi 源码。
- 原生商家页是编译好的 Nuxt 产物，源码不在仓库里。改版全部通过中间件注入脚本和样式实现（第 12 节）。

## 1. 为谁做、做成什么样

| 项 | 决定 |
|---|---|
| 主要用户 | 不懂设计的门店老板，其次是不太专业的运营 |
| 用户每天做的三件事 | 做一条内容 → 找到做好的内容 → 把内容发出去 |
| 后台结构 | 「做内容 → 管内容 → 发出去」：创作页只管生成；素材库（原料）和作品库（成品）负责存放；GEO 与门店营销负责分发。同一个能力只留一个家，别处用小入口和弹窗调用 |
| 视觉方向 | 原稿的 Mac 应用质感为准；布局可以比原稿更好，不必照搬 |
| 主题 | 默认且只维护白色（浅色）；商家移除深色、跟随系统、皮肤、动态背景及其设置入口。短剧/画布仍按适用范围保持原样 |
| 颜色 | 全站固定一套配色，不随 OEM 品牌色变化 |
| 设备 | 只做桌面端；手机版以后单独出（头像菜单里「手机端」保留并置灰） |
| 质量要求 | 用户体验优先，每个细节反复推敲；不图省事，能不复用就不复用旧实现 |

产品概念（影响页面归属）：
- **品牌**是 GEO 营销的单位（GEO 针对整个品牌做）。
- **门店**对应种草卡：NFC 打开 H5，顾客一键把成片带到抖音等平台发布，或选门店亮点，由 AI 结合品牌知识库写点评后跳转小红书发布。
- **空码**就是门店码牌：系统批量预生成 URL 空码，商家扫码自行绑定，代理商也可代绑；种草卡绑定与码牌激活是同一个流程。一家店可以有多张种草卡（URL 绑定或空码绑定）。
- **员工任务**：把成片派给员工，通过微信公众号通知员工去发布；作品核验保持手工审核。
- **充值**多由代理商代充，入口只放头像菜单「会员与充值」和工作台 TP 卡。

## 3. 设计原则

- **作品是主角，界面退后。** 结构、间距、字号、对齐全站一致。
- **颜色克制。** 页面约 90% 黑白灰。强调色只用于：AI 生成按钮、当前导航、图表主序列、焦点、选中。普通主按钮用墨黑。
- **材质不扁平。** 卡片不是纯色块：微竖向渐变 + 发丝描边 + 两层环境投影 + 顶部高光（见第 6 节）。
- **用信息代替句子。** 需要强调时用数字、状态、期限、变化来表达，而不是写一句说明。
- **按状态显示，不写死。** 后端配好就正常可用，没配好显示「待开通」并说明怎么开通。
- **先让用户知道代价。** 会扣 TP 的操作，按钮上或旁边显示预计消耗。

## 4. 禁止项（交付前逐条自查）

1. 线性图标放在浅色底框里。图标统一用 Semi 实心款，不加底框。
2. 纯色卡片（扁平白块、浅色色块卡片）。
3. 大段说明文字；重复标题意思的副标题。
4. 标签、状态用「浅色底 + 同色文字」。状态一律「小圆点 + 文字」。
5. 主题色大面积铺开（浅紫底卡片、整块紫色背景、紫色描边卡片墙）。
6. 「图标 + 标题 + 一句描述」的等权卡片墙；到处是「开始创作 →」箭头链接。
7. 渐变文字、emoji、发光描边、装饰性插画占首屏。
8. 文字溢出、操作入口被裁切或显示不全。
9. 写「算力」「积分」。统一叫 TP。
10. 假数据。没有接口的信息不显示（例如素材库不放「存储空间」）。
11. 页面 CSS 里写死颜色。只用 `--ui-*`（颜色 Token）和 `--uk-*`（组件库材质变量）；需要新颜色先加到 Token 或组件库，再引用。
12. 同一种操作在不同页面用不同颜色或图标（见第 6 节「按钮语义」）。

### 有作用的标注要保留，并做成有设计感的样式

| 类型 | 用途 | 样式 | 例子 |
|---|---|---|---|
| 状态 | 能不能用、进行到哪 | 圆点 + 文字 | ●待开通 ●生成中 ●已送达 |
| 提醒 | 需要用户去处理的事 | 带图标的一行提示条，右侧放操作按钮 | 「3 名员工收不到通知」【去处理】 |
| 价值 | 让功能更有吸引力 | 小徽章 | 新 / 热门 / 推荐 / 包收录 |
| 计费 | 做之前知道花多少 | TP 图标 + 数字 | ⬢ 10/张 · 预计消耗 ⬢ 40 |
| 数据 | 用数字代替一句话 | 标题或页签旁的小号数字 | 视频 12 · 本周 +3 |
| 规则说明 | 偶尔需要解释的规则 | ℹ 图标，悬停显示，不常驻 | 收录要求 ℹ |
| 引导 | 空的时候告诉怎么开始 | 空状态本身就是操作区，附一行格式/限制 | 「拖到这里，或点击上传」+「MP4、MOV · 单个不超过 100MB」 |

## 5. 功能处置四法

每页先回答「用户来这页要完成什么」，定好主角，其余功能按下表处理。

| 处置 | 什么时候用 | 例子 |
|---|---|---|
| 融合 | 同一件事被拆在多页、多个入口或两套数据 | 数字人「克隆音色」和剪辑「我的音色」合成一个音色库 |
| 收起 | 后端没接、需服务商开通，或店老板基本用不到 | GEO 的 B2B、官网 SEO |
| 小入口 + 弹窗/抽屉 | 不离开当前页就能完成的辅助动作 | 知识库、选素材、员工管理、回收站 |
| 有作用的标注 | 提醒、状态、价值点、计费 | 见第 4 节 |

收起分三级：
- **后端有、需服务商开通**：入口保留，灰色 +「待开通」状态点；点击弹窗（K9）说明能做什么、怎么开通。
- **后端完全没有**：不单占一页，集中到所属页面的「更多」，标「即将上线」。
- **店老板基本用不到**：去掉入口或折叠进「更多」；旧地址保留跳转，不出现死链。

## 8. 页面骨架

1. **概览型**（工作台）：标题行 → 焦点卡 + 数据卡 → 常用 → 两栏（趋势 / 进行中）→ 最近作品。
2. **列表型**（素材库、作品库、种草卡、任务、门店）：
   - 标题行（大标题左，主操作右：次要按钮在前，墨黑主按钮在后）。
   - 下划线页签，带数量；页签行末尾放小入口（如回收站）。
   - **一张卡片 = 一个窗口**（访达式）：左侧本页导航栏（文件夹/分组）+ 发丝线 + 右侧内容区。两栏永远等高，不做两张高度不一的卡片并排。
   - **本页导航与全局侧栏颜色相反**：全局侧栏是灰底、选中项白色；本页导航是白底、选中项浅灰。本页导航**不加底色**，避免和灰色侧栏形成两层侧栏。
   - 本页导航标题行与右侧工具条在同一水平线上；导航栏随页面滚动时吸顶。
   - 内容区：工具条（搜索、筛选下拉、排序、视图切换）→ 生效的筛选显示为可删除的胶囊 + 「清除筛选」→ 网格/列表 → 分页。
   - 多选后底部浮出墨黑批量操作条（全站唯一一种，M3）。
3. **创作型**：左配置卡 360–400px（底部固定「预计消耗 + 生成按钮」）+ 右结果卡（本次 / 历史）。
   - **库存型（作品库「成片」）**：成片组是给发布渠道供货的库存，首屏就是成片组卡片，不用侧边文件夹。卡片：封面堆叠、组名、状态（充足 / 偏少 / 用完了 / 还没有成片）、「还能用 N 条」、四段库存条与图例、低库存提示、用途（员工任务、自动化计划）、底部「派给员工」「补充」。顶部提醒条只在 2 个及以上组需要处理时出现，单个组只在卡片上提示，不重复。点进去是组详情：返回链接、组名与状态、设置 / 派给员工 / 补充成片，五个统计块（全部 / 没用过 / 已派发 / 已发出 / 已用满）同时是筛选。之后文案库、图文库、文章用同一套。
4. **编辑器型**（视频剪辑）：主导航保留用户手动选择的展开/收起状态，不因进入或离开编辑器自动切换；左素材、中编辑、右预览 + 全局设置；唯一的生成按钮在右上角，显示数量和 TP。

## 9. 交互细节约定

**网格与卡片**
- 作品/素材缩略图 1:1、圆角 14，铺满；透明图下面垫浅色棋盘格，避免看起来像坏图。
- 悬停才浮出勾选框（左上）、更多操作（右上）、上下渐变遮罩；视频左下常驻毛玻璃时长。
- 进入多选状态后，所有卡片都显示勾选框，点卡片即切换选中（不再打开预览）；选中卡片外圈强调色描边、图片内缩。
- 卡片下：名称一行省略；meta 一行（尺寸 · 时长，客户端读取文件得到；读不到时显示格式）；状态点靠右；标签最多两个（彩色圆点 + 名称）。
- 音频类默认列表视图，行内播放按钮（墨黑圆形），同时只播一个，播放中显示细进度线。

**加载与空状态**
- 进入页面立即显示与最终布局同形状的骨架屏（网格是方块，列表是行）；不要等所有接口返回才出内容。列表和元数据并行请求。
- 数量在拿到真实值之前**留空**，不先显示 0。
- 翻页、筛选时保留旧内容并降低透明度，不闪白。
- 空状态就是操作区：真实可点、可拖放；标题说清「哪里没有什么」（如「「门店实拍」还没有视频」），附格式与大小限制。筛选后为空时显示「没有符合条件的…」+「清除筛选」。

**弹窗与浮层**
- 弹窗打开时关闭所有提示气泡。焦点优先给第一个需要填写的输入框，其次主按钮；没有主按钮的抽屉，焦点给面板本身，**不要让关闭按钮带焦点框**。
- 回车提交单输入框弹窗；Esc 关闭最上层；菜单支持上下键。
- 不可逆或影响范围大的操作才用确认框（如删除标签）；可从回收站恢复的操作不确认，直接执行并 toast 提示。
- 菜单项不可用时置灰并写原因（如「删除文件夹 · 需先清空」），不隐藏。

**上传**
- 整页可拖放，拖入时内容区出现半透明遮罩，写明「松开上传到「当前文件夹」」。
- 右下角上传托盘：并发 2，每个文件有进度、失败可重试；全部成功后先收起，再自动消失；有失败时一直保留。
- 前端校验格式和大小，**与后端规则一致**，不合规的直接跳过并提示，不浪费上传时间。

**预览（K2）**
- 深色全屏 Quick Look 式；顶部标题、序号、操作（下载、编辑、移入回收站）、关闭；左右键切换；底部 meta（尺寸·时长、文件夹、标签、上传时间）。

**成片库存与使用状态**（作品库、派给员工共用）
- 四种状态，颜色和顺序全站固定：**没用过**（成功绿）→ **已派发**（强调色，派给员工了还没发出）→ **已发出**（深灰，员工提交了作品链接或审核通过）→ **已用满**（浅灰，达到每条最多派发次数）。
- 「已派发」只算进行中的任务，取消任务会退回；「已发出」一旦提交就算数。
- 预警线：每个组单独设置「没用过的少于几条时提醒」，默认 5，填 0 不提醒。
- 每条成片在卡片下显示状态，派发或发出过的再带平台小图标和次数（例：抖音 1），用来避免同一条在同一平台反复发、被限流。
- 派给员工默认**按组**：从组里按「没用过 → 已派发 → 已发出」的顺序自动挑，每位员工一条、不重复；没用过的不够时提醒并给「先补充」。单条成片上的「派给员工」保留。
- 「补充成片」菜单：数字人口播（带 `?film_library=组ID`，生成后自动进组）、视频剪辑、AI 视频（这两个暂时要做好后手动归组）、自动化计划（定时批量补充）。

**状态记忆**
- 视图方式（网格/列表）等个人偏好存在 localStorage，读写都包 try/catch。

## 12. 技术接入

**结构**
- 商家端原生页面是编译好的 Nuxt 产物，源码不在仓库里。改版通过中间件注入脚本和样式实现。
- `app/common/http/middleware/MerchantPortalMiddleware.php` 往 `public/pc/index.html` 注入 `public/merchant/*.js/css`，每个文件带 `?v=` 版本号（格式 `u<MMDDHHMM>`）。
- 注入顺序：`ui-kit.js` → 各新页面脚本（如 `materials-v2.js`）→ `workspace.js`。**新页面脚本必须在 workspace.js 之前**，否则首次加载时旧页面会先挂上。样式：`ui-v2.css` → `ui-kit.css` → 各新页面样式。

**新页面怎么挂**
- `UK.page({key, match, mount, update})`：把 `.uk-root` 挂进 `main.ia-content`，给 main 加 `.uk-host`，CSS 隐藏 main 里其他子元素。同一页内切换子路由（如素材类型）用 `router.push`，走 `update()` 刷新。
- **同一页里的子视图（页签）用 `history.replaceState` 改地址，不走 Nuxt 路由**：走路由会让原生页重新渲染，新页面被迫重挂载（闪白、丢选择和滚动位置）。不同页面之间才用 `UK.go`。
- `window.UK_OWNS()`：旧脚本挂载前询问。`workspace.js` 的 `mount()`、`finished-library.js` 的 `check()` 开头已加同样判断。例：`if(window.UK_OWNS&&window.UK_OWNS()){if(root)cleanup();return;}`。
- 旧素材库 `MerchantMaterialLibrary` 不能删：剪辑页用它当素材选择器（K1 做好后再替换）。

**接口约定**
- 所有请求必须带 `tenant_id`（如 `/api/user/center` 不带会报「租户不存在」）。本地访问地址也要带 `?tenant_id=1`（`http://127.0.0.1:8090/...?tenant_id=1`）。
- `UK.api`：query 里带 tenant，header 带 token，JSON body 自动并入 tenant_id。
- `merchantWorkspace` 系列沿用 workspace 的调用方式：`/api/merchantWorkspace/<action>?...&tenant_id=`，JSON body 不加 tenant_id，靠会话 cookie。
- 素材库接口：
  - GET `folders?kind` → `{lists[{id,name,parent_id,count,sort}], total, unfiled}`；`labels`；`library?kind&folder_id&trash&page&page_size(24|48|72)&keyword&usage&label_id&sort(name)` → `{lists, count}`；`choices?kind=store&keyword=`
  - POST `batch{kind,action:move|label|trash|restore,ids,folder_id|label_ids}`、`folderSave{id,kind,name,parent_id,sort}`、`folderRecycle{id,kind,restore:'0'|'1'}`、`folderReorder{kind,ids}`（ids 为整棵树按顺序展开）、`labelSave{id,name,color}`、`labelRemove{id}`、`materialSave{id,kind,name,folder_id,tags,content,file_ids,store_id,label_ids}`
  - 上传：multipart POST `/api/merchantWorkspace/upload?tenant_id`，字段 `file, kind, folder_id`（`attach_only=1` 只传文件不建素材）
  - 列表行字段：`id, name, files[{id,name,url}], used, labels, label_ids, folder_id, store_id, tags, content, file_ids, create_time`。没有文件大小和尺寸，尺寸/时长只能在客户端读取。
- 后端校验（前端须一致）：图片 jpg/jpeg/png/webp/gif ≤20MB；视频 mp4/mov ≤100MB；音频 mp3/wav/ogg/flac/aac/m4a/opus ≤50MB；文件夹名 ≤60 字；标签名 ≤30 字；素材名 ≤100 字；关键词 ≤255 字。
- 作品库接口：
  - GET `workspace_asset/feed?type=(空|image|video|audio)&source=&keyword=&page&page_size(24|48|72)` → `{lists[{ref,source,tool,type,title,url,cover_url,width,height,duration,create_time,film,trashable,favorite,label}], count, counts{image,video,audio}, tools[{source,name,type,count}]}`。剪辑成片 `url` 为空，要用 `merchantPublishing/delivery?ref` 取临时签名地址（会过期，前端按过期时间缓存）。
  - POST `workspace_asset/update{refs,action:trash|restore}`：**body 不能带 tenant_id**（会被判为无效字段），tenant 只放 query。回收站列表来自 `workspace_asset/state` 的 `supplemental` + `states.trashed_at`。
  - 成片：`merchantPublishing/films?library_id&source&keyword&page`（每页固定 24）、`libraries`（含 unfiled）、`catalogs?kind=video|image_text|copy|topic|finished_image&trash`（库 + 次数统计）、`catalogSave{kind,id,name,parent_id,sort,max_uses}`、`catalogRecycle{kind,id,restore}`、`move{library_id,refs}`。
  - 派给员工：`merchantPublishing/staff`（含 wechat_bound）→ `create{request_key,title(≤80),content(≤500),staff_ids,refs,platforms(douyin|kuaishou|xiaohongshu),copy_text|copy_folder_id,topics|topic_folder_id,due_time,deadline}`；文案为空时必须选文案库。

**GEO 的结构（`geo-v2.js`）**
- 一个 `UK.page`（`key:'geo'`，`own:true`），按地址 hash 分区：诊断 `#diagnose` / `#diagnose-records` / `#diagnose-evidence`，效果 `#effect` / `#effect-jobs`。地址带 `brand_id`（品牌切换只影响 GEO，R4）。

  - `views`：`{hash: [区名, 页签名]}`；`alias`：旧 hash → 新 hash；`intents`：旧 hash → 意图名（如 `#ai-keywords` 打开拓词弹窗）。hash 里的 `?a=b` 参数随意图一起传给区模块，然后地址被规范化。

  - 区模块的点击属性用自己的前缀（内容区用 `data-gc-*`），不要用 `data-goto`、`data-kb`、`data-more` 等 `geo-v2.js` 已占用的名字。
- 没被新版接管的 hash 继续由旧 Semi 应用显示（`geo-semi-loader.js`），新版接管后旧版自动让位。
- `call()` 抛出的错误带 `answered: true` 表示服务器明确拒绝（可换新 `request_key`）；没有这个标记表示网络问题，重试要沿用原 `request_key`。

**GEO 接口**（`/api/merchantGeo/<action>?tenant_id&brand_id`，控制器 `app/api/controller/MerchantGeoController.php`，服务在 `app/common/service/merchant/geo/`）
