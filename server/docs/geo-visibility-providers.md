# 国内自动可见度诊断接入与配置（2026-10-17）

2026-10-19 已新增用户指定的 GEO 服务商 API v1.3 协议，配置位置统一为「接入能力配置 → AI 可见度监测」。最新协议、19个平台版本与费用规则见 [GEO 服务商接入说明](geo-partner-integration.md)。以下保留原模力指数直连的历史说明，其退款与轮询规则不适用于新协议。

已实现模力指数公开协议适配、异步采样、结果入库、定期复测与原生算力结算。当前本地没有真实供应商域名、Token和可售监测SKU，所以默认不启用、不发起真实采样。离线契约测试通过不代表真实账号联调通过。

海讯社继续提供原媒体发布链路。发稿回执不能代替 AI 平台实际回答、引用和复测证据。普通文本模型API、网页搜索API同样不等于消费者端可见度采样。

模力指数文档的域名是 `{API_DOMAIN}` 占位符，不能直接填进后台，也不默认猜测某个业务域名。需由供应商签发实际地址。文档存在平台清单与历史下架记录不完全一致的情况，本轮仅接入较明确的 DeepSeek、豆包、元宝、千问、Kimi 网页端，以及前四个的移动端；文心一言等仍保留人工采样。正式上线前须核实当日账号实际可用模型。

本接入固定 `search` 模式并开启截图，避免模式附加费用混用一个价格。文档列出的国内基础采样为0.117元，截图另加0.117元，深度思考还会另加0.117元；**这是供应商成本说明，不能直接作为商家算力售价**，以签约及实际对账为准。供应商是否要求预充值、额度、并发、失败扣费及转售/OEM许可，需开户时书面确认。系统不替供应商自动充值。

## 管理后台怎么配置

1. 向域明科技获取正式 HTTPS API 域名、Bearer Token，确认 API 权限、商用转售范围、模型可用性与截图保留时间。不要把密钥贴到聊天或前端代码中。
2. 在原有算力市场找到 **GEO自动可见度诊断（模力指数）**。安装会注册默认下架的 `aigc_geo / visibility_cn` 产品及 `geo_visibility_cn_per_call` SKU。按原标准设置平台供 OEM 价格、OEM商家售价并上架；计量为“一个问题 × 一个平台 / 次，search含截图”。不会建立另一套充值或钱包。
3. 平台进入 `/platform/geo/config` → **国内AI可见度监测** → 本级自配，填写产品ID、SKU ID、供应商域名（如 `https://实际API域名`，不含路径或端口）和 Token。产品/SKU会按注册记录预填。凭证加密保存，留空保留已存Token。
4. OEM自有账号：进入 `/admin/geo/config?tenant_id=实际OEMID`，选择本级自配并填写本OEM的域名与Token及原市场产品/SKU。商家价格仍使用本OEM原市场设置。
5. OEM借用平台账号：平台在同一能力下授予目标OEM“允许使用/借权”；OEM将该能力切为“借用平台配置”。缺少授权、平台停用或OEM主动停用都不能自动兜底。OEM后台看不到平台Token。
6. OEM可向实际代理授予该能力的**使用权**。本轮自动监测的配置权固定在平台/OEM，代理不能持有或自配此能力的密钥。其他原有能力的代理配置策略不受影响。
7. 平台/OEM的 **GEO任务与消耗** 可核对任务与原消费单。代理按原所属商家层级查看记录；各商家只看自己项目、报告、回答与消费，不返回供应商密钥、上级配置或平台成本。

## 商家使用与定期反馈

- 独立使用：数据中心 → **AI可见度诊断**，先完善品牌名称、行业、产品服务、目标客户，填写实际问题和目标平台，保存范围，再预览次数与原市场费用并确认采样。独立诊断也保存为可继续优化的项目。
- 闭环使用：一键GEO优化 → 确认范围 → **预览自动诊断与费用**。支持同范围自动采样与原来的人工采样入口，已录入人工样本的轮次继续人工完成。
- 自动范围当前为“全国 / search联网 / 网页端或已支持App端”。“全国”表示供应商随机国内节点，不能宣称某个城市的曝光。旧项目的地区、默认模式等范围已冻结时，不偷偷换模式或平台；请另建明确的自动范围。
- 按问题×平台拆分持久化任务。每轮最多150次，提交确认后整轮原生预扣。每个有效回答按一次结算；明确失败退回该次预扣；GET轮询不另收费。未知受理状态保留预扣，避免盲目重发。
- 完成后自动保存回答、截图链接、时间、参考来源与实际引用，并封存全部或部分成功报告。失败/缺失组合单列，不进入提及率分母；品牌问题和自然发现问题分组。品牌提及不自动判为推荐，信息准确性保留待人工核验。
- 审核诊断后生成并确认优化计划。在 **复测与反馈 → 定期自动复测** 设置每1/7/14/30天、1至52轮、每轮算力上限，总授权周期不超过366天，再明确确认。启用设置本身不收费，每次到期才提交并预扣。
- 到期使用相同问题、平台、端与模式；按最新市场报价预览。超上限、余额不足、配置/授权变化、计划变更、项目暂停或已有未封存轮次时停止，显示原因，需重新确认。错过的历史周期不补跑，不累计突发调用。
- 已提交的供应商任务在项目暂停或停止未来复测后仍可取回原结果；未启动的任务取消并退款。阶段报告对比真实基线和最近封存复测，方法或覆盖不一致时明确提醒，不将变化直接归因于发稿。
- 反馈为站内项目报告，不会自动向客户发短信、邮件或发稿。原来的内容创作、媒体发布和人工核验入口继续独立使用。

## 超时、对账和部署

- 提交使用固定 `consumerTaskId`，成功受理后只按原 `taskId` 查询，不跟随供应商返回的任意轮询地址或重定向。
- 提交超时/进程中断进入待核对，禁止自动再次 POST。平台/OEM具备“核对自动监测原任务回执”权限的管理员，在任务详情按展示的幂等键核对供应商订单，填写原任务ID和说明后 **取回原任务结果**。该动作只查询，不重新下单或追加预扣；题目、平台、模式、时间及任务ID仍由后端校验。
- 原授权配置变化、超过24小时自动取回窗口或原消费单已处理时，不允许借新账号查询旧任务，需按原消费单和供应商流水人工对账。未查清前不伪造退款或成功，原轮次保持待核对。
- 截图只保存供应商URL，文档当前说明约180天有效；未下载为永久资产。部署前应确认数据留存与长期报告归档策略。
- 执行 `php scripts/install-merchant-geo.php` 安装增量表和菜单，保持已有配置/售价不变。运行原 `php think merchant-geo:work` 常驻进程，新增异步轮询和每60秒检查一次复测/报告。部署代码后重启此进程。无需创建Codex计划任务。
- API域名必须HTTPS；服务器校验公网IPv4并固定DNS解析结果，禁代理、跳转、内网/保留地址，限制响应体及超时。凭证只用于服务端请求。

接口：GET `visibilityOptions`、`visibilityPreview`、`visibilityRecords`；POST `visibilityStart`、`visibilitySchedule`，统一走 `/api/merchantGeo/` 原鉴权与防跨站写入；管理端 POST `geo.config/recover` 单独授权。

验收：`tests/geo-visibility.integration.php` 和 `tests/geo-visibility.http.php` 使用隔离身份、注入模拟传输及原生钱包流水验证；不调用真实外部接口。正式启用仍需管理员配置真实账号、按一题一平台完成实际验收并核对原消费单。
