## 种草卡和门店装修

目前种草卡是“门店 + 视频/图文素材 + 话题”的内容组合管理，支持新增、编辑、回收站和恢复。保存种草卡并不会生成第三方平台发布任务。

装修中已经列出以下发布入口，但当前是装修配置和预览，没有相应的作品发布适配：

| 入口 | 当前缺口 |
| --- | --- |
| 抖音视频 | 发布授权或分享接入、素材携带、标题/话题/门店信息、跳转发布页、发布结果确认 |
| 快手视频 | 同上，需要快手对应接入链路 |
| 小红书视频及图文笔记 | 对应分享/发布链路、内容携带、发布结果确认 |
| 视频号 | 对应分享/发布链路及结果确认 |
| 朋友圈图文 | 图片与文案交付、受支持的分享流程；不能把打开微信视为发布成功 |
| 大众点评、携程笔记 | 对应平台正式能力或允许的跳转方式；携程入口当前默认关闭 |

此外尚缺整个种草卡对客链路：可分享的公开落地页/二维码、按卡片获取可发布素材的受控接口、平台选择与发布记录。装修中的普通 HTTP/HTTPS 自定义链接只提供链接跳转，不具备自动携带作品发布的能力。

员工“任务发布”是另一条已有链路：商家分配任务 → 员工领取并下载成片 → 手工发布 → 回填 HTTPS 作品链接 → 商家审核。当前没有自动验证作品已发布的上游回调或查询接口。

代码定位：

- `public/merchant/workspace.js`：种草卡表单和编辑/回收站操作。
- `app/common/service/merchant/MerchantWorkspaceService.php`：种草卡本地保存及归属校验。
- `app/common/service/merchant/MerchantStoreDesignService.php`：装修功能入口目录。
- `public/merchant/store-designer.js`：`actionPreview` 仅展示入口预览。
- `app/common/service/merchant/MerchantPublishService.php`：员工任务、手工提交作品链接、商家审核。

## 建议实施顺序

1. 先补齐 GEO 已有适配的真实配置、计费上架和 OEM 权限；关键词指数和自有账号发布单独确认供应商。
2. 种草卡先完成公开落地页、二维码、素材交付和发布记录，再优先接抖音、快手、小红书。
3. 每个平台分别确认当前官方权限和分享/发布方案；跳转成功、用户确认发布、服务端确认发布要分开记录。官方不提供结果回调时保留手工提交链接与审核，不伪造发布成功。

本报告确认的是本地缺口，不代表各平台均开放同一种发布 API；具体接入方案需在实施时核对官方文档及账号已有权限。
