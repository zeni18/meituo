# GEO 独立能力配置与开通

更新：2026-10-17。继续 `D:\AI营销中台\likeadmin-aigc` 的 AIGC 二开项目。本地完成代码、权限与离线契约验证；未购买外部服务、未充值、未真实发稿或进行收费监测，未部署生产。

## 在哪里配置

2026-10-19：平台与 OEM 的“接入能力配置”已加入“GEO营销”分组，左侧列表可直接切换 AI创作、网页检索、国内AI可见度监测、关键词指数、自有账号发布。分别进入 `/platform/integration/config#geo-text` 与 `/admin/integration/config?tenant_id=实际OEM#geo-text`。复用原 GEO 表单及 API，原配置、逐项借权和代理授权不迁移；未适配能力保持禁用。原 GEO 配置菜单已合并，`geo/config` 旧链接自动跳转统一配置页；仅有 GEO 权限的员工仍能进入，但不会因此增加其他能力权限；`geo/jobs` 任务页保持独立。配置项切换支持键盘与未保存修改确认，刷新保留 URL 中的当前能力。

| 身份 | 入口 | 可以做什么 |
| --- | --- | --- |
| 平台 | `/platform/integration/config#geo-text` | 平台自有能力配置，逐能力授予/撤销 OEM 借权 |
| OEM | `/admin/integration/config?tenant_id=实际OEM#geo-text` | OEM 自配或选择借用平台；逐代理授权使用和维护代理自己的配置 |
| 代理一、二级 | 同 OEM 路径，以代理身份登录 | 查看本级状态；只有获得 OEM“允许使用 + 允许自配”时才能维护自己配置；无上级密钥和转授权接口 |
| 平台 / OEM / 代理 | 各自后台的 `geo/jobs` | 按实际权限查看任务、结果、原消费单及费用状态 |
| 商家 | `/ai/geo?tenant_id=实际OEM` | 品牌、事实素材、问题、AI创作与拓词、内容、任务与消耗、人工证据、海讯社发稿 |

OEM 借权与代理授权是两层独立许可。给 OEM 平台借权，不会自动让其所有代理都获得该能力。一级代理的任务查询包括当前直属商家及当前下级二级代理商家；二级代理仅自身直属商家。配置所有权始终是当前登录身份，不接受前端伪造的 tenant/agent ID。

原有员工也须分配新菜单权限：`geo.config/lists`、`save`、`grant`、`jobs`。平台和 OEM 的 grant 含义不同；代理没有 grant 权限。商家接口不存在供应商配置动作。

## 先开通文章生成、AI拓词、改写

2026-10-19：用户确定三项功能先统一使用 DeepSeek Flash 官方直连，已实现独立凭证与原市场计费。完整说明见 [DeepSeek Flash 接入](geo-deepseek-flash.md)。

1. 在“接入能力配置 → GEO营销 → AI拓词 / 文章生成 / 改写”选择“本级自配”和“DeepSeek Flash 官方直连”。模型产品 ID 自动带出，填写官方 API Key 并保存。密钥加密保存，商家与借用方无法读取。
2. 在原算力市场维护“DeepSeek Flash（GEO官方直连）”输入、输出两个 Token SKU 的平台/OEM售价并上架。新 SKU 默认下架，不自动设置免费服务；界面价格均按实际安装的单位显示。原市场统一上游选项保留，旧配置仍沿用原模型及凭证。
3. 如果统一走平台：平台保存本级模型后，在该能力下填写目标 OEM ID，勾选“允许使用 / 借权”，保存授权。OEM 切换为“借用平台配置”并保存。
4. 商家属于代理时，OEM 在同一能力下填写代理 ID，勾选“允许使用”。需要代理选择自己的模型时再勾选“允许维护代理自己的配置”。代理可自配或继承 OEM。
5. 商家进入“AI创作与拓词”，选择文章写作、AI拓词、改写、参考结构创作；选择本商家事实素材并提交。结果在“任务与消耗”查看，经人工确认入问题库或内容库。改写/参考创作目前粘贴原文，不自动抓取第三方账号或文章。

计费调用原 `MarketTextModelRuntimeService`，归属 `aigc_geo`，并关联 `oem_geo_job`。根据实际供应商 Token usage 与原市场执行时价格结算，使用原用户/OEM 算力账户及消费流水。没有 usage 时维持原系统待结算规则，不按字数伪造。入库、手工编辑品牌/事实/问题不扣费。

**本地已登记 DeepSeek Flash 专用模型，但 API Key、售价及授权由管理员完成。** 未齐备时提交按钮关闭；代码与离线验收不代表已经真实联通供应商。

## 再开通网页检索（博查）

1. 到[博查官方开放平台](https://open.bochaai.com/)注册/开通 Web Search，在控制台取得 API Key。当前调用额度、单价、预存/套餐以账号合同和控制台为准，尚未确认具体商务报价。
2. 安装会在原算力市场登记“GEO网页检索（博查）”和一个 `per_call` SKU，**默认下架**。平台在原市场设置每次的平台对 OEM 价格并上架；OEM 在原市场设置自己的销售价格。没有可售 SKU 时系统不调用博查。程序不自动填写供应商成本，不自动给用户免费调用。
3. GEO“网页检索 / 素材溯源”配置表自动带出该市场产品/SKU ID。平台或 OEM/获自配授权代理填写自己的 API Key，选择“本级自配”并保存；需统一平台账号则按上节的逐项借权流程配置。
4. 商家选择“网页检索”，页面显示原市场每次算力价格，提交后预扣。结果保留网页标题、摘要、来源链接和检索时间，可核实后整理为事实素材。

服务器固定调用 `POST https://api.bochaai.com/v1/web-search`，Bearer Key，不允许自定义主机或跳转，不自动重试收费调用。成功时在原消费单结算；明确拒绝时走原钱包返还；超时、未知响应维持待核对，管理员先检查供应商记录和原消费单，不应先重新提交。自配供应商账户的供应商费用由其账户承担；市场 SKU 仍定义本系统服务算力售价，双方商务成本需分别核对。

没有调用供应商的测试不代表联调成功。首次真实试用应由管理员用确定的少量查询核对供应商账单、消费单、结果链接及原余额变化。

## 安装、常驻与验证

```sh
php scripts/install-merchant-geo.php
php think merchant-geo:work
```

独立安装/修复可用 `php scripts/install-geo-capabilities.php`；不会覆盖已保存配置、借权或价格。Windows `scripts/local-start.ps1`会以隐藏进程启动 GEO worker。生产与 Web 共用数据库和现有凭证加密主密钥，按原进程管理方式常驻。借权不会把 Key 复制给 OEM/代理；每次实际执行检查当前权限、配置版本与归属。停用、撤权、配置不完整都不会自动回退到平台。

状态含排队、执行中、完成、失败、待核对；唯一请求键防止重复入队。运行中断不会自动重发付费请求。已得到结果但结算待核对时保留内容，避免重复生成。没有定时监测和自动批量发布行为。

凭证复用已有 AES-GCM vault，使用 `geo:agent_id:capability` 独立用途标识。必须保留现有加密主密钥文件/环境变量；配置接口只返回“已保存”，不回显 Key。任务给下级的响应不包含平台成本、密钥和内部配置快照。

本轮本地验证：`tests/geo-capabilities.integration.php` 42 项；`tests/geo-capabilities.http.php` 38 项；`tests/geo-billing-shards.php` 5 项；原 GEO 38 项、海讯社 84+49 项、代理隔离 97 项、原分表业务 8 项回归通过，共361项。集成测试中原生钱包扣费/返还全部事务回滚；HTTP 测试身份清理完毕，未请求外部 API。

分表验证发现原 BaseModel 的钱包模型查询切换了物理表，但 ORM 保存时丢弃查询 scope，导致余额写回共享表。修复限于 User、UserAccountLog、TenantPointLog 的分表后缀保存及插入/更新绑定，并检查 OEM 身份和分表是否存在；没有改价格、余额账户结构或扣费算法。5项独立分表检查确认同数字ID共享用户不受影响，原分表业务8项和代理97项回归通过。
