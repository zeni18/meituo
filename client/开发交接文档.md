# 开发交接文档

本文用于在新会话中快速接续 LikeAdmin AIGC SaaS 的新工具开发、前后端打通、UI 调整、应用发布和系统版本发布工作。新会话可直接搜索“开发交接文档”，先读本文，再按实际任务读取对应 skill。

## 新会话启动

建议在新会话开头直接说明：

```text
请先阅读根目录《开发交接文档.md》。涉及 LikeAdmin AIGC SaaS 新工具开发时使用 likeadmin-aigc-saas；涉及 PC 工具页 UI 时使用 ai-product-image-ui-design 和 ai-frontend-experience；涉及任务、计费、存储、供应商时分别使用 ai-task-queue-callback、ai-billing-quota、ai-asset-storage、ai-provider-integration；涉及应用包或系统发布时使用 ai-app-release-packaging 或 likeadmin-aigc-saas-update-packaging。
```

常用 skill：

1. `likeadmin-aigc-saas`：应用骨架、app_code、API、菜单权限、安装开通、前端入口。
2. `ai-product-image-ui-design`：PC AI 商品图系工具页、上传区、任务与作品、深色工作台。
3. `ai-frontend-experience`：PC/租户/平台/移动端交互、空态、错误态、轮询、删除下载。
4. `ai-task-queue-callback`：AI 任务状态、轮询、回调、重试、结果同步。
5. `ai-billing-quota`：平台成本、租户点数、用户余额、退款回滚。
6. `ai-asset-storage`：生成结果、授权 URL、存储字段、软删除、下载。
7. `ai-provider-integration`：`aigc_image`、`aigc_video`、`aigc_llm` 供应商服务接入。
8. `ai-app-release-packaging`：单应用打包、manifest 版本、应用中心发布。
9. `likeadmin-aigc-saas-update-packaging`：系统更新包、完整包、私有更新源、仓库推送。

## 仓库边界

- 当前开发仓库可包含 `server/`、`pc/`、`tenant/`、`platform/`、`uniapp/`，只用于开发、构建和打包。
- 前端源码仓库是 `https://gitee.com/likeadmin/likeadmin-aigc-org.git`，只能同步 `pc/`、`tenant/`、`platform/`、`uniapp/`。
- 服务端发布仓库是 `https://gitee.com/likeadmin/likeadmin-aigc.git`，根目录必须是 `server/` 内部内容。
- 服务端 GitHub 镜像是 `likeadmin-hub/likeadmin-aigc`，服务端发布推送 Gitee 后也要推同一提交到 GitHub。
- 发布仓库同步必须使用临时 clone 或专用 worktree。不要在开发仓库里为了发布而删除前端根目录、重置、清理或改造成服务端仓库结构。

## 新工具开发总流程

1. 先分析静态页面字段，保留用户确认的业务字段，不额外暴露模型、质量、价格包、自定义尺寸等控制项，除非用户明确要求。
2. 确定 `app_code`，必须 lowercase snake_case，例如 `aigc_one_click_cleanup`、`aigc_product_suite`。
3. 新建独立应用骨架：
   - `server/app/apps/{app_code}/manifest.json`
   - `server/app/apps/{app_code}/api_schema.json`
   - `server/app/apps/{app_code}/menus/`
   - `server/app/apps/{app_code}/permissions/`
   - `server/app/apps/{app_code}/migrations/`
   - `server/app/apps/{app_code}/frontend/`
   - `pc/apps/{app_code}/`
   - `tenant/src/apps/{app_code}/`
4. 用户端 API 统一走 `/api/app.{app_code}...`。
5. 租户后台 API 统一走 `/tenantapi/app.{app_code}...`。
6. 平台端业务 API 只在确实需要时加 `/platformapi/app.{app_code}...`。
7. 所有接口同步写入 `api_schema.json`，菜单、权限、frontend entries 都要带 `app_code`。
8. PC 工具卡和装修工具入口要跳转到真实路由，例如 `/ai/tools/{app_code}`，不要继续进入静态模板。
9. 需要 AI 能力时依赖基础应用：图片工具依赖 `aigc_image`，视频工具依赖 `aigc_video`，AI 帮写/优化依赖 `aigc_llm`。
10. 控制器不直接调第三方供应商，统一走业务 service 和 provider 抽象。

## 应用购买安装逻辑

- 不再给新工具做“默认应用自动开通/自动安装/自动加入基础应用清单”的特殊逻辑。
- 按正常应用中心逻辑走：平台未购买的应用也可以展示，但提示未购买；购买后未安装提示未安装；购买后才能安装。
- 平台已购买并安装的应用，才能配置套餐并供租户购买开通。
- 租户开通时要展示需要花费的点数。
- 套餐开通点数可以为 `0`，续费点数也可以为 `0`，不要强制校验续费点数必须大于开通点数。
- `system_default` 是系统特殊内置应用，不能把普通新工具也按它处理。

## 后端数据规范

- 表名使用 `la_{app_code}_*`。
- 租户数据必须有 `tenant_id`，用户任务必须有 `user_id`。
- 任务表通常记录：输入参数快照、模型规格快照、价格快照、数量、总点数、上游任务 ID、状态、错误信息。
- 结果表必须记录生成资源和存储信息：`storage_scope`、`storage_engine`、`storage_domain`。
- 前端只使用后端返回的授权 URL，不直接拼存储地址。
- 删除优先软删除本应用记录，保持租户和用户隔离。
- 单张结果删除和整任务删除要分清：多图任务 hover 删除只删当前结果，底部全部删除才删整条任务。

## 计费与生成规范

- 平台成本取基础能力应用的当前规格估价，例如 `aigc_image` 或 `aigc_video`。
- 用户售价取当前独立工具的租户后台定价。
- 提交前检查租户点数和用户余额。
- 真正扣费和回滚走已有共享点数服务，不直接改 `user_money` 或 `tenant.point_balance`。
- 图片工具优先使用 `AigcImageService::generateWithBillingOverride`。
- 视频工具优先使用 `AigcVideoService::generateWithBillingOverride`。
- 任务状态聚合：
  - 全部成功：`success`
  - 全部失败：`failed`
  - 生成中：`running`
  - 部分成功：`partial_failed`
- 列表、详情和轮询都要同步上游任务状态，成功后写入结果，并避免重复写入。
- 失败要返回用户能理解的错误，不要只显示“生成失败”或破损图。

## PC 工具页 UI 规范

整体按 AI 商品图深色工作台风格实现，不做营销落地页。

- 页面首屏就是可用工作台。
- 左侧编辑区固定约 `403px`，右侧任务与作品自适应。
- 左侧结构：紧凑标题、可滚动表单、底部 sticky 生成栏。
- 主面板背景 `#0f0f0f`，次级卡片 `#171717` / `#1a1a1a`，边框 `#222`，主生成按钮白底黑字。
- 主要区块间距约 `32px`，字段内部约 `14px`。
- 不使用大渐变、大 hero、营销卡片、嵌套卡片。
- 文字不能重叠，按钮不能溢出，长标题要截断。

### 上传区

- 所有工具上传空态使用 AI 换发型同款添加图标：`@/assets/images/icon/Add.svg`。
- 空态主提示文字固定为“本地上传”。
- “图库上传”保留为单独按钮。
- 具体上传用途写在字段标题，例如“上传商品图”“上传模特图”，不要写在上传框空态里。
- 多图上传工具沿用多图上传逻辑：上传框高度固定，上传成功的图片显示在上传框下面的网格中，不要把上传框撑高。
- 图库上传对图片工具只展示图片资产。
- scoped 样式下要确保上传卡内部类能被命中，必要时使用 `:deep(...)`。

### 选项卡

- 消除选项、视角选项、视频类型、套图模块等后台可配选项要用图文卡片，不要只做纯文字。
- 封面读取顺序：`cover_url || cover_image`。
- 未配置封面时显示暗色占位，不内置示例素材。
- 租户后台封面维护使用素材选择器，不用纯 URL 输入框。

### 下拉框

- PC 深色工作台内的下拉框必须保持项目深色风格。
- 不要出现默认浏览器或 Element 原生浅色下拉窗破坏风格。
- 平台端/租户端后台则遵循各自 Element 组件风格。

## 通用任务与作品模板

图片类工具右侧“任务与作品”尽量统一使用：

```text
pc/components/ai-workspace/tool-task-panel.vue
```

统一协议：

- `mode: 'single' | 'multi'`
- `id`、`title`、`badge`、`createTime`、`status`、`statusText`、`sizeLabel`
- `references[]`：原图/参考图缩略图
- `prompt`：任务描述文本
- `items[]`：作品列表，单图也放 1 条
- 回调：`refresh`、`edit`、`regenerate`、`preview`、`downloadOne`、`downloadAll`、`deleteOne`、`deleteAll`

展示规则：

- 右侧标题固定“任务与作品”。
- 空态文案：“暂无创作，开启你的创作”。
- 作品框固定 `240px × 240px`。
- 圆角 `14px`，图片 `object-fit: cover`，不能露出直角底色。
- hover 操作条保留底部圆角。
- 生成中只显示 loading 占位，不渲染 `<img>`，不能把上传图/参考图当结果图。
- 失败显示失败占位和友好错误。
- 底部按钮统一为：`重新编辑 / 再次生成 / 全部下载 / 全部删除`。
- 作品 hover 按钮统一为：`下载 / 删除`。
- 单图任务的单张删除可以等价删除任务；多图任务的单张删除只删当前作品。
- 右侧只能有一层背景。旧模板外层如果包了背景，需要加 host class 去掉外层背景、边框、阴影和内边距。

## 下载规范

- hover 下载只下载当前作品。
- 底部“全部下载”下载整条任务内所有成功作品，不包含原图/参考图。
- 多图工具不能只下载第一张。
- 后端 ZIP 容易受私有存储、签名 URL、远程读取失败影响；若用户要求走前端，则使用前端打包方案并实际测试。
- 前端打包建议使用 `jszip` 等成熟包，必须处理无 URL、请求失败、空结果、部分失败，并给出明确提示，不能静默无反应。
- 单图任务底部全部下载可以下载单张作品。

## 租户后台规范

- 常见菜单：基础配置、选项/类型/模块/预设管理、价格配置、任务记录。
- 若产品明确说价格放基础设置，就不要再保留价格配置页。
- 基础配置一般包含：启停、默认通道/模型/清晰度/比例、提示词模板、负向提示词。
- 价格配置一般只维护当前工具独立售价，不暴露基础应用售价。
- 封面、模特预设、图片资源使用素材选择器。
- 任务记录支持状态、用户关键词、选项/类型/模块筛选，支持详情、重试、删除。
- 产品宣传视频后续规则：售价单位按秒，租户可输入并调整；默认时长不作为可选配置项；价格配置并入基础设置。

## 本轮工具规则速查

- 一键消除 `aigc_one_click_cleanup`：上传 1-10 张图；消除选项多选；按图片数计费，不按选项数计费；多图任务。
- 商品多角度 `aigc_product_multi_angle`：单张商品图；视角多选；补充描述选填；每个视角生成一张；按视角数计费；多图任务。
- 服饰套图 `aigc_fashion_lookbook`：最多 6 张服饰图；1 张模特图或预设模特；比例；补充描述选填；每张服饰图匹配同一模特生成一张；多图任务。
- 产品宣传视频 `aigc_product_promo_video`：上传产品图；比例；时长；视频类型；描述词；AI 帮写/优化；依赖 `aigc_video`；单视频任务。
- 无缝扩图 `aigc_outpaint`：上传图片；只选后台模型适配比例；不保留自由滑块/自定义比例；单图任务。
- AI 商品套图 `aigc_product_suite`：商品图最多 3 张；平台、国家/地区、语言、比例、核心卖点、模块多选；每个模块生成一张；按模块数计费；多图任务。
- 局部重绘 `aigc_local_redraw`：上传原图；绘制蒙版；描述词；但当前生成接口不传 mask，按图生图走。
- AI 试衣 `aigc_fitting`：文件在 `pc/apps/aigc_fitting/FittingCreator.vue`；图/组图/自定义要用指定分段样式；已选模特固定在底部生成按钮上方；保留原有已选模特 UI，只改布局；数量字号 `14px`；选中模特卡右上角有删除按钮。
- AI 换发型 `aigc_hairstyle`：上传素材走素材库/图库逻辑时要和其他工具统一，不能出现按钮逻辑不一致。
- 已移除入口工具：照片转手绘、爆款复刻、模特试鞋、一键买家秀、一键买热点。

## 应用发布与系统发布

用户说“构建编译发布新版本”“打包发布系统并提交推送代码”时，默认按系统版本发布处理，而不是只构建本地。

标准流程：

1. 查看 `git status --short --branch`，确认当前改动范围。
2. 根据改动运行构建：
   - PC：`cd pc && npm run build`
   - 租户后台：`cd tenant && npm run build`
   - 平台后台：`cd platform && npm run build`
3. PHP 改动跑语法检查：

```bash
docker exec bt php -l /www/wwwroot/likeadmin_aigc_saas/<path>
```

4. 准备系统更新 staging，确保 `update.json`、`sql/data`、`sql/structure`、`menus`、`rollback` 完整。
5. 正常发布必须递增版本，不要复用旧版本。不要随意传 `--version` 或 `--no-bump`，除非是未发布失败包重建。
6. PC 构建产物必须完整进入系统包：
   - `server/public/pc`
   - `server/public/_nuxt`
   - `server/public/media`
7. `full_replace_dirs` 要包含对应目录，不能只打包 `index.html`。
8. 打包系统更新包示例：

```bash
python3 /Users/likeadmin/.codex/skills/likeadmin-aigc-saas-update-packaging/scripts/package_update.py system \
  --repo . \
  --source-dir runtime/system_update_staging/<version> \
  --out-dir runtime/release_packages/system/<version> \
  --incremental \
  --base-version <previous_version> \
  --full-replace-dirs public/pc,public/_nuxt,public/media
```

9. 校验系统包：

```bash
node scripts/verify-system-update-package.mjs runtime/release_packages/system/<version>/system_<version>.zip
```

10. 发布私有更新源：

```bash
python3 /Users/likeadmin/.codex/skills/likeadmin-aigc-saas-update-packaging/scripts/publish_private_release.py system \
  --package runtime/release_packages/system/<version>/system_<version>.zip \
  --metadata runtime/release_packages/system/<version>/system_<version>.metadata.json
```

11. 如果改了 `pc/tenant/platform/uniapp` 源码，还要同步前端源码仓库 `likeadmin-aigc-org`。
12. 提交并推送开发仓库代码。发布仓库推送必须用临时 clone，不要污染开发仓库。

发布注意：

- `server/config/project.php` 和 `server/upgrade/version.json` 要与发布版本一致。
- 版本更新内容必须面向用户，使用 `1.`、`2.`、`3.`，不要写 API、表名、SQL、文件路径、任务 ID、内部错误。
- 不能把 `.env`、runtime 上传文件、`node_modules`、日志、发布 zip 大包提交进源码仓库。
- GitHub 镜像有时会因网络或 SSH 超时失败；失败时要明确报告为镜像推送阻塞，不要说发布完全成功。

## 发布前检查清单

按范围选择执行：

```bash
git status --short --branch

rg -n "CREATE TABLE|ALTER TABLE|INSERT INTO|source_menu_key|app_code|frontend_entries|package" \
  server/app/apps server/upgrade server/public/upgrade server/public/install/db/like.sql server/app/platformapi/db/tenantData.sql

unzip -l runtime/release_packages/system/<version>/system_<version>.zip | rg \
  "(update.json|signature.json|like.sql|tenantData.sql|upgrade|sql/structure|migrations|manifest.json|menus)"
```

前端源码仓库推送前：

```bash
git diff --cached --name-only | rg '(^|/)(node_modules|dist|\.nuxt|\.output|\.vite)(/|$)|(^|/)\.env(\.|$)|^server/|^runtime/'
git ls-files | rg '^(server|runtime)(/|$)'
```

这些命令不应返回禁止路径。

## 常见踩坑

- 新工具只写了源码，没有安装到应用注册表或没有购买安装流程，前端会提示“应用未购买”或“未安装”。
- 为了避免“应用未购买”而强行默认开通新工具是错误方向，普通新工具要走平台购买安装和租户开通。
- PC 改了源码但系统包没包含完整 `public/pc` 和根级 `public/_nuxt`，线上会仍显示旧版本或不显示更新。
- 任务生成中不能回退显示参考图，否则用户会以为生成成功或看到破损图。
- 多图任务单张删除不能触发重新生成。
- 全部下载不能只取第一张，也不能失败无提示。
- scoped 样式里上传卡被封装成子组件后，样式可能没命中，导致上传按钮、图标、图库逻辑和其他工具不一致。
- 后台配置图片封面不要用 URL 输入框，统一素材选择。
- 局部重绘当前上游不用传 mask，避免因 mask 参数不支持导致生成失败。
- 平台端和租户端同类按钮、菜单选中态、返回行为要保持一致，尤其应用市场和应用管理三级菜单。
