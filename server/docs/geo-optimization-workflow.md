# 一键 GEO 优化项目

本地实现日期：2026-10-17。工作台“一键GEO优化”创建可续办项目；“优化项目”查看已有项目。各独立资料、创作、媒体和数据页面继续保留。

## 使用路径

1. 品牌资料：复用企业知识库。保存品牌、行业、产品服务与目标客户后继续，不填虚构资料。
2. 检测范围：修改本地模板/已有问题，选择平台、地区、网页/App端和模式，可填品牌别名；确认后冻结项目品牌和问题范围。
3. 可见度诊断：支持人工采样及模力指数异步自动采样，保存实际回答、证据链接、观察时间与核对结论。原始证据同时保存到现有人工证据库。自动监测未接通时明确提示，不向普通模型API提问后冒充消费者曝光。
4. 封存诊断：缺少采样的平台/问题标为未覆盖，需明确确认部分样本；品牌问题与非品牌问题分别计算。封存后不能覆盖，后续另建复测。
5. 优化计划：按实际样本生成规则建议（不是AI付费分析）。可修改/增删任务、依据、期限和执行范围。保存后审核确认，产生不可覆盖的计划版本和待执行任务，不自动扣费。
6. 执行任务：可进入原AI创作队列，任务与消费单自动关联；结果仍需审核入库。可关联已有文章、素材和媒体订单。内容任务关联文章后验收，媒体任务需真实已发布订单，复测任务需本计划确认后的已封存复测。信息核验任务需人工说明。
7. 复测与反馈：原问题/平台/环境继续采样，与基线分组对比；无复测时明确待观察。可即时汇总进度，确认计划后按7/14/30天生成站内报告。支持暂停和继续项目。

## 周期报告的边界

`merchant-geo:work` 每60秒检查一次到期项目，生成站内进度报告并安排下一周期。报告只读取实际任务与已封存采样，不触发模型、监测或发稿调用，不发送短信/微信/邮件，不产生周期扣费。暂停项目和失去商家营销授权的项目不自动出报告。

模力指数正式公开协议已实现适配，需平台/OEM配置实际域名、Token和原市场按次SKU后开通；当前没有真实凭证，不宣称完成外部联调。配置权限、OEM借权和已有算力市场保持原实现。规则计划和人工编辑不扣费，真实AI创作与媒体下单继续走原计费和确认流程。

## 数据与接口

新增 `oem_geo_project/cycle/sample/plan/action/action_link/progress_report`。每次读写使用服务器tenant/user约束；计划、采样和执行记录不能跨商家关联。项目revision防止并发覆盖，创建request_key防重；已确认计划快照、已封存诊断不可覆盖。

- `GET /api/merchantGeo/workflow`：项目列表；传id读取项目详情。
- `POST /api/merchantGeo/workflowAction`：建档、范围确认、采样、封存、计划修改与确认、执行记录关联、暂停/继续及报告。
- `POST /api/merchantGeo/workflowGenerate`：验证当前已确认任务后复用原GeoJobs，队列创建和关联在同一事务中完成。

默认每商家最多50个项目，每项目最多50个计划版本、3000条采样；详情页显示最近300条采样，完整原始证据仍在独立证据库，封存统计覆盖本轮全部样本。名称提及按确认的品牌/别名匹配，推荐与事实准确性为人工核验口径；界面不将其标为自动监测结果。

## 安装与验证

执行 `php scripts/install-merchant-geo.php` 安装新增表。前端在 `frontend/geo-semi` 执行 `npm run build`；常驻 `php think merchant-geo:work`（改代码后重启）。本地已重启GEO worker，未部署生产。

`tests/geo-workflow.http.php` 的74项检查通过，覆盖HTTP权限/方法/同源、跨商家隔离、幂等、版本冲突、真实采样和分组统计、未审批不执行、证据验收、计划版本、复测归属、周期报告、暂停和零隐式扣费。原工作空间68项回归、导航契约、主题同步8项和生产构建通过。测试身份与数据已清理，无外部付费调用。浏览器核对了工作台入口、建档和检测范围、原独立入口、深浅色主题及下拉框；没有为演示填造商家事实或诊断结果。
