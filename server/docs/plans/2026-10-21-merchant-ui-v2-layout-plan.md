# 商家端 UI V2 布局优化方案（素材库 / 作品库 / 视频剪辑 / 共用弹窗）

日期：2026-10-21。状态：待评审，尚未改动任何业务页面文件。
依据：`docs/merchant-ui-v2.md`（2026-10-20 定版）；三份现状盘点（读代码得出，没有在浏览器里逐页实测）；恢复的工作台、AI 商品图、素材库三页原稿。
视频剪辑页没有完整原稿，只有四页画布缩略图，本方案对它的视觉细节没有原稿依据。

## 0. 结论先行

1. 四个范围的共同问题不在配色，在结构：同一件事有多个入口，主操作被埋进弹窗，弹窗里套弹窗，一页里最多出现 4 个搜索框，选择类弹窗里塞着管理功能。
2. 视频剪辑改动最大。从点“立即剪辑”到真正提交云合成要点 5 次、穿过 3 层弹窗，V2 压成 2 步。
3. 三个“共用弹窗”现在都不是共用组件。选素材弹窗只有视频剪辑在用；企业知识库抽屉有 GEO 和品牌中心两套互不相干的实现；TP 确认至少有 5 套。V2 各收成一个。
4. 视频剪辑目前不扣商家 TP。生成按钮上只显示数量，不放任何 TP 数字，否则就是虚构价格。
5. 有 10 个需要你拍板的决策点（第 9 节），其余按建议执行。

## 1. 你的三条要求，落成可检查的规则

| 要求 | 落成的规则 | 自查方式 |
|---|---|---|
| 不用线型图标加浅色底框 | 四个范围内的图标全部实心，没有常驻底框；Feather 线性图标（`/merchant/icons/*.svg`）全部替换；音频、配音卡不再用“圆形浅绿底加线性图标” | 搜索这四个范围对 `icons/` 和 `mask` 的引用，应为 0 |
| 卡片不图省事做成纯色 | 每种容器对应一种材质（第 2 节），不允许全站一个 `background:#fff` | 逐个容器核对是否落在材质表里 |
| 布局以用户实际体验为先 | 每页先写“用户要完成的事”和最短路径，再排版；砍并清单每条都写体验理由 | 第 4 到 6 节每页开头的任务路径 |

## 2. 材质表（卡片不做纯色）

数值取自恢复原稿 `Main.dc.html`、`Create.dc.html`、`Library.dc.html`，行号见盘点。规范第 5 节的“靛紫网格渐变”在原稿里没有网格纹理，只有渐变加同心圆线框，所以本方案不做网格。

| 容器 | 材质 | 关键写法 |
|---|---|---|
| 基础卡（表格、表单、列表容器） | 白底三层阴影，不靠纯色 | `box-shadow: 0 0 0 1px rgba(22,23,29,.04), 0 1px 2px rgba(22,23,29,.04), 0 8px 24px -10px rgba(22,23,29,.10)`，圆角 16。远影 spread 取负，阴影收在卡片下方 |
| 作品卡（素材、作品、生成结果） | 图片铺满，底部渐变遮罩放标题，悬停浮出操作，图片 500ms 轻放大 | 遮罩 `linear-gradient(180deg, rgba(10,10,16,0), rgba(10,10,16,.62))`；角标深色玻璃 `rgba(16,17,24,.48)` 加 `backdrop-filter: blur(8px)`；悬停按钮 `rgba(255,255,255,.92)` |
| 音频、旁白卡（没有封面图） | 石墨渐变封面加时长，不用图标加底框 | `linear-gradient(145deg,#2A2C36,#16171D)`，顶部 1px 内高光 `inset 0 1px 0 rgba(255,255,255,.08)`，左下时长，悬停出现实心播放键。这是灰黑色材质，不占用强调色 |
| 堆叠卡（一组镜头、一组作品） | 多层错位，后层用同色系渐变，不用纯灰块 | 后两层 `left/right: 7px / 14px`，`top: -5px / -10px`，用 `linear-gradient(180deg,#E4E5EB,#D3D5DE)`。原稿作品堆叠是纯灰块，这里升级 |
| 焦点卡（每页最多 1 张） | 三层背景加外紫影加同心圆线框 | 沿用 `workbench-v2.css` 的 `.wb-focus` 写法，高度原稿 208，现 CSS 200，统一为 208。四个范围里只有视频剪辑右栏的“当前任务”用一张，其余三个不用 |
| 批量操作条 | 深色浮条加内描边 | `#16171D`，`box-shadow: 0 20px 40px -12px rgba(22,23,29,.55), inset 0 0 0 1px rgba(255,255,255,.06)`，圆角 14，`position: sticky; bottom: 24px` |
| 创作页或编辑器底部固定区 | 渐变加顶部分割线 | `linear-gradient(180deg,#fff,#FBFBFD)` 加 1px `#F0F1F4` |
| 空态与拖放区 | 虚线描边加极淡渐变，兼作上传入口 | 不用插画。空态本身就是可拖放的上传区 |
| 加载占位 | 流光 | `linear-gradient(110deg,#ECEDF2 25%,#F8F8FB 42%,#ECEDF2 60%)`，背景尺寸 220%，1.8s，尊重 `prefers-reduced-motion` |
| 页面画布 | 底色 `--ui-bg` 加页头一层极淡径向光 | `radial-gradient(60% 120px at 20% 0, rgba(91,92,246,.06), transparent)`。透明度压在 6%，不属于“主题色大面积铺开”。这是判断题，见决策 D9 |

现状缺口：`ui-v2.css` 里没有基础卡、作品卡、堆叠卡、批量条、素材勾选框、下划线页签、流光占位这些通用类，焦点卡、数据卡、作品卡的现成类带 `.wb-` 前缀且限定在 `main.ia-content.wb-active` 里。第一批工作是把它们提成通用类，见第 8 节。

## 3. 图标

现状有三套互相不一致：

- 侧栏 `nav-v2.js` 是内联 SVG 填充款，符合规范。
- 页面内（素材库、剪辑、作品库）全是 Feather 线性描边，用 CSS `mask` 着色。
- 原稿用 Material Symbols Rounded 字体，设置为 `FILL 1, wght 500`，即实心。

规范写的是“Semi Icons 填充款”，但原稿和侧栏用的都不是它，我也无法确认现有实心图标是否真来自 Semi Icons。2026-10-14 的图标对照文档暂用 Heroicons 24/solid（MIT，来源已登记）。图标库选型见决策 D3。无论选哪套，规则固定：

- 业务页面一律内联 SVG，`fill: currentColor`，不用 `mask`，不用字体。
- 尺寸 14 / 16 / 18 / 20；默认 `--ui-text-3`，选中 `--ui-accent` 或 `--ui-text`。
- 不加底框。悬停态可出现 `rgba(22,23,29,.05)` 的背景，这是交互反馈，不是常驻底框。
- 不用多色图标。现有剪辑页补充卡的金色、绿色图标取消。
- 保留的例外：方向、关闭、搜索等功能符号可用同族实心款，不做特殊处理。

## 4. 全局规则（四个范围共用，先定下来再画页面）

| 规则 | 内容 | 解决的现状问题 |
|---|---|---|
| 一个视图一个搜索框 | 作品库“全部作品”页现在最多同时出现 4 个搜索框 | 用户不知道搜的是哪一个 |
| 页签统一为下划线加数量 | 素材库类型页签、作品库子页签现在是胶囊式，作品库一级页签是下划线，同产品两种风格 | 风格不一致，违反规范第 6 节 |
| 回收站统一在页签行右侧，文案固定“回收站”加数量 | 现有四种回收站交互：页面按钮、原生“最近删除”、成片库回收站按钮（文案随状态翻转）、图文库行内“移入回收站” | 找回误删的路径不可预期 |
| 预览统一为一个 Lightbox | 现有至少五套预览：素材库、营销内容、文章、发布管理、原生详情 | 不能上一个下一个，素材库预览还会自动播放 |
| 删除先执行，再给 8 秒撤销，多次撤销排队 | 现在撤销链接会被下一条通知冲掉 | 删文件夹后无法反悔 |
| 主按钮用近黑，强调色只给 AI 生成 | 素材库现在主按钮是强调色实心 | 违反规范第 1 节 |
| 标题下不写说明文字 | 空态“标题加一句话”、弹窗说明条、配置面板描述 | 违反规范禁止项 4 |
| 空态就是拖放上传区 | 不再用图标加标题加说明加按钮 | 违反规范禁止项 5、6 |
| 分页档位固定 24 / 48 / 72，带总数和跳页 | AI 作品保留滚动加载，因为它是原生编译页 | 素材库没有跳页，三种分页方式混用 |

## 5. 素材库（列表型）

### 5.1 用户要完成的事

1. 创作时快速找到一条素材（视频、图片、音频、旁白）。
2. 一次传很多文件，并立刻归到正确的文件夹。
3. 整理：移动、打标签、重命名、删除。
4. 知道这条素材有没有被用过。
5. 误删后找回。

## 6. 作品库（列表型）

### 6.1 用户要完成的事

1. 找到某条成品，去发布或下载。
2. 把成品归入库，设置每条内容最多使用几次。
3. 给员工分配发布任务，看用了多少、还剩多少。
4. 回看 AI 生成历史，收藏、打标签。
5. 找回误删内容。

### 6.2 现状的结构性问题

- 页面是三层叠起来的：原生资产页（编译产物，源码不在仓库里）、注入的页签、按页签换的内容。
- 页签是两层：`全部作品 | 成片 | 图文 | 文章`，图文下面再套 `图文库 | 图片库 | 文案库`。
- 切到任一成品页签后，原生的“收藏 / 上传 / 最近删除”、搜索、筛选整体消失，要点回“全部作品”才恢复。
- 话题库、拓词库在页签里没有位置，只能靠深链或品牌页进入。
- 成片页签显示的是“库”的卡片，不是视频本身。看一条视频要经过：库卡片、视频管理弹窗、预览弹窗，3 层。
- “全部作品”页上方是“营销内容”聚合区，下方才是 AI 作品，两个网格两个搜索。聚合区在浏览器里一次性拉全量，库大了会慢。

## 7. 视频剪辑（编辑器型）

### 7.1 用户要完成的事

1. 选好素材，配好字幕、声音、时长。
2. 看预览，确认大致效果。
3. 一次生成若干条成片。
4. 中途离开不丢东西。
5. 知道云端任务进行到哪、成片在哪。

### 7.2 现状要点

- 没有唯一的生成按钮。顶栏“立即剪辑”其实只生成本地编排，不剪辑；真正提交云合成要点 5 次：立即剪辑、开始编排、提交云合成、勾选确认、再次提交，穿过 3 层弹窗。
- 第一次点“提交云合成”只出现一个勾选框，并用红色错误样式提示，把正常步骤当成失败。
- 未保存标记“保存工程 *”藏在收起的“工程”下拉里，没有常驻状态，也没有自动保存。
- 多个主按钮抢权重：立即剪辑、预览排版、空态“添加素材”。
- 同一动作多个入口：云任务与成片 3 处，字幕样式 3 处，转场 / 滤镜 2 份，我的音色 2 处，空态里“添加素材”和“从素材库选择”点同一个动作。
- 弹窗互相覆盖：在“云任务与成片”里点“填入口播文案”，若有未保存修改会触发确认，云任务列表被关掉且轮询停止，取消后不恢复。
- “转场 / 滤镜”弹窗里只有 4 个调色预设可用，转场、随机滤镜、花字都未适配。
- “AI 生成选题”按钮永久禁用。
- 命名混用：AI视频剪辑、视频剪辑、智能剪辑、AI短视频。页面里实际有两个标题，靠 CSS 隐藏一个。
- 主导航没有按规范收成 72px 图标栏。
- 不扣商家 TP，费用由云账号承担。

## 8. 共用组件（补规范第 8 节）

三个共用弹窗现状都不是共用组件，下面是各自的 V2 定义，以及它们依赖的几个基础组件。

### 8.1 选素材弹窗 `MaterialPicker`

现状：由素材库组件的 selection 模式加视频剪辑私有的弹窗外壳拼成，只有视频剪辑用。弹窗里带完整管理功能（标签库、回收站、新建文件夹、文件夹排序、移动分组），页脚有两套计数和两套按钮，确认按钮在没选任何素材时仍可点，会把素材池清空，标题下有说明文字。

V2：

- 尺寸 960×640，窄屏全屏。左文件夹栏可收起，右侧网格，底部固定“已选托盘”。
- 去掉所有管理功能。保留：搜索、文件夹切换、上传、类型限制。
- 已选托盘显示缩略图，可拖动排序、可单个移除，计数只有一处“已选 3 / 100”。
- 确认按钮：选择没有变化时置灰；要清空素材池走显式的“清空已选”。
- 单选（上限 1）时，选新的会替换旧的，并在托盘里短暂显示“已替换”。
- 上传中不禁止关闭，上传在后台继续，托盘里显示进度。
- 超上限的提示显示在弹窗内，而不是素材库内部的错误行。
- 调用签名保持 `picker(allowed[], initialIds[], max, onChoose(ids[]))`，调用方不用改。

### 8.2 企业知识库抽屉 `KnowledgeDrawer`

现状有两套：GEO 创作台里的 Semi 右侧抽屉，宽 1080，关闭没有未保存保护；品牌中心的原生 JS 居中弹窗，有未保存保护。两者字段相近但不相同（GEO 7 个字段，品牌中心 8 个知识分类）。

V2：

- 一个抽屉，右侧滑出，宽 720，所有调用方共用。
- 内容分组：基本信息、企业介绍、产品与服务、目标客户与地区、竞品与差异事实。
- 每个文本域带“AI 强化”，沿用品牌中心的对比与采用流程，提交前走 `TpConfirm`。现状品牌 AI 强化提交即计费，没有确认。
- 页脚固定“取消 / 保存”。现状 GEO 是“完成，返回创作”，没有取消。
- 有改动时关闭先确认。
- GEO 的 7 字段与品牌中心 8 分类是否同一份数据、`profileSave` 和知识文档接口是否同源，我没读后端，见 D5。落地前必须先确认，否则合成一个抽屉会写错表。

### 8.3 TP 确认 `TpConfirm`

现状：至少 5 套，标题 5 种写法，宽度、层级、遮罩点击行为各不同，只展示“每 Token 单价”，用户看不到这次大约花多少，单位文字还取后端 `point_unit`，默认值是“算力”。

V2：

- 宽 440，标题固定“确认消耗”。
- 内容：项目名称、数量、预计消耗合计（TP 图标加数字）。有真实报价才显示数字；没有真实报价显示“按实际用量计费”，不虚构。
- 按钮“返回调整 / 确认并开始”，确认按钮用近黑，不用 AI 渐变，渐变只给真正触发生成的那个按钮。
- 请求带 `quote_token`、`accept_charge`、`request_key`，沿用 GEO 创作台已有的幂等做法。
- 单位固定显示 TP，不再读 `point_unit`。
- 视频剪辑的云费用同意不属于 TP 确认，用同一骨架但标题写“云服务费用”，内容写“由对应云账号承担，不扣商家 TP”，两件事不混。

| `Toast` | 提示与撤销 | 队列化，撤销 8 秒 |
| `TpText` | TP 显示 | 见下 |

`TpText` 的原因：`tp.js` 用 MutationObserver 把“40 算力”改成“图标加数字”，要求数字和单位在同一个文本节点。我推断 React 把 `{price} {unit}` 渲染成多个文本节点，所以只会命中“单独的算力改成 TP”，得到“0.5 TP”，而不是规范要求的图标加数字。这是读代码推断，没有在浏览器里验证。V2 新代码直接输出 `\uE000 40`，不依赖运行时替换。

## 10. 落地顺序与验收

顺序：

1. 通用类与组件：基础卡、作品卡、堆叠卡、批量条、勾选框、下划线页签、流光、图标。从 `workbench-v2.css` 提取，去掉 `.wb-` 限定。

3. 共用弹窗：`MaterialPicker`、`TpConfirm`、`KnowledgeDrawer`（取决于 D5）。
4. 作品库。
5. 视频剪辑。改动最大，放最后，也是唯一缺完整原稿的页面。

每个阶段的验收：

- 改动 `public/merchant/` 现有文件前，先备份到 `D:\AI营销中台\output\ui-v2-backup\<时间>\`，`public/merchant/` 不在 git 里。
- 逐条核对 `merchant-ui-v2.md` 第 2 节 8 条禁止项，以及本文第 1 节三条规则。
- 在浏览器里实际打开，检查桌面与手机宽度，检查减少动态效果。
- 数量、状态、消耗用真实数据，不用参考稿示例数字。
- 保留业务能力：素材库的归属约束与事务校验、成片库的使用次数统计、剪辑的工程乐观锁与云合成流程，接口字段、价格、数据库不变。
