# 门店列表对照实现与验收

参考为登录态小魔推 `https://xiaomotui.com/#/store`，实查门店列表、新建抽屉、批量创建、员工列表与新增员工。用户要求融入现有商家端；不增加页面标题横幅，保留本系统主题、主导航、原有门店 ID 与素材关系。

## 页面和业务

- 独立入口 `/ai/stores?tenant_id=1`，横向门店行展示 Logo、名称、电话、地址、添加时间、到期时间及操作。名称、创建日期区间、状态、回收站筛选，10/20/50 条分页。
- 新建／编辑使用右侧抽屉，支持真实 Logo 上传、营业时间、电话、地址、坐标、POI、联系人、简介、启停状态。省市区当前分别填写；没有引入不明来源或过期行政区数据。坐标格式是“纬度,经度”，链接至腾讯拾取坐标工具。
- 批量创建提供 CSV 模板，接受 UTF-8 CSV 和单工作表 XLSX；单文件 2MB、单批 100 家。上传只解析预览，确认后才落库；整批校验失败全部回滚。拒绝 XLSX 公式、过大解压内容、过多压缩条目、超限／稀疏行。Logo 在创建后补充。
- 员工资料按门店和商家隔离，支持新增、编辑、启停、批量新增、筛选、本页 CSV 导出、回收／恢复；恢复时检查手机号冲突。没有创建员工登录账号，也没有伪造扫码绑定、发布或转化统计。
- 装修支持主题色、宣传语、介绍及电话／地址／营业时间展示开关，保存草稿并预览。未发布公开落地页。
- 回收门店保留其员工、资料和关联素材；恢复后继续使用原 ID。

## 已确认的申请规则

用户确认“续期和码牌激活由 OEM／代理审核办理，商家提交申请”。

商家填写说明后提交，查看申请历史和办理结果，待审核可撤回；同门店同类型仅允许一条待审核申请。OEM 在商家列表上方的“门店申请”处理所属 OEM 的申请。一级代理覆盖直属与名下二级代理商家，二级代理仅覆盖自己的商家；审核按当前商家归属查询，不能使用传入代理 ID 绕过权限。OEM 员工沿用商家列表／管理商家权限，未授权员工无法读取或审核。

审核结果包括通过办理、驳回；审核说明必填。续期通过必须指定新的有效到期日期，且晚于当前有效期与今日，事务内同时写入到期时间和审核记录。码牌当前登记线下办理编号／凭证，明确标记 `manual_record`，不宣称已调用外部激活服务。不自动扣费，不生成支付订单。已处理或撤回的申请不能重复审核。

## 实现位置

- 前台：`public/merchant/store-directory.js`、`.css`，由 `workspace.js` 的 stores 分支挂载，随路由销毁。
- 商家接口：`MerchantWorkspaceController` 的 store* 扩展，继续执行原登录、商家应用授权、同源写入检查。
- 服务：`MerchantStoreService`、`MerchantStoreRequestService`。
- 审核端：`public/oem/directory.js`、`DirectoryController`，代理由 `AgentAdminMiddleware` 严格白名单派发。
- 新表：`oem_merchant_store_meta`、`oem_merchant_store_staff`、`oem_merchant_store_request`；迁移 `upgrade/20261016_merchant_store_directory.sql`。
- 已在本地安装；其他环境可执行 `php scripts/install-merchant-stores.php`。总 OEM 安装脚本也包含迁移。CSV/XLSX 解析需要现有 PhpSpreadsheet、PHP ZipArchive；测试环境已具备。

参考截图：`runtime/local/evidence/store-reference/01-list.jpg`、`02-create.jpg`、`03-staff.jpg`。本地：`runtime/local/evidence/store-local/` 中的列表、抽屉、批量预览、员工、浅色、375px 手机及 OEM 审核截图。

- 列表并排核对采用同一 1781×1244 视口，保持“筛选和创建按钮 → 横向门店行 → 页脚分页”层级，100px Logo 和约 148px 行高。现有系统深浅主题代替参考的白紫皮肤；不复制第三方门店资料、Logo、二维码或业务资产。保留本系统侧栏，不复制参考的广告标题。
- 发现并修复双重留白：原 `ia-content` 自带 48px 横向内边距，叠加门店面板内边距导致页面过窄；增加仅门店页生效的宿主类，路由销毁时移除。
- 文字／间距：主内容 12–15px，资料抽屉 17px 标题，复用现有字体与线性图标；按钮及选中／焦点跟随 ia 主题变量。下拉框复用 shared/select，已实测浅色与深色展开、选择、筛选。
- 手机：375×812，无文档横溢，筛选换行、行信息分组、触控按钮至少 44px；抽屉全屏，表单独立滚动、底部操作可用。原侧栏在手机为覆盖层，使用原收起入口关闭。验收后视口恢复，主题恢复经典深色。
- UI 实操：创建并上传 Logo，编辑回填；员工新增及批量新增；装修草稿保存回填；CSV 上传预览及确认创建；提交续期并撤回；商家提交码牌申请→OEM 队列→驳回→商家历史回显。无浏览器 JavaScript 错误。
- `php -d extension=gd -d extension=zip tests/merchant-store.http.php`：80 项通过，包含跨商家、跨代理、跨 OEM、无权限 OEM 员工、审核重放、申请撤回、批量回滚、真实 XLSX、超限稀疏行、员工恢复冲突等。命令只允许隔离本地数据库，测试创建的商家、代理、管理员、门店和临时文件已清理。
- `php tests/merchant-workspace.http.php`：128 项回归通过，包括原素材／种草卡关系、现有 AI 前端及原路由登录保护。PHP／JS 语法检查通过。
- 浏览器使用本地体验商家创建的 3 家测试门店已移入回收站，员工／草稿随门店保留；测试申请已撤回／驳回，无待处理验收申请。未修改第三方系统数据，未产生付费云调用。

明确剩余能力：外部 NFC 激活与配置路径、公开门店落地页发布、员工扫码绑定／平台发布统计、数据通知通道尚未接入。对应入口明确展示状态，未伪造可用二维码或激活结果。省市区联动选择与更完整的装修模块可在确定数据源和公开门店页方案后补充。

验收结论：本轮列表、资料、导入、员工档案、装修草稿和人工申请审核闭环通过。上列外部业务能力仍为待接入状态。
