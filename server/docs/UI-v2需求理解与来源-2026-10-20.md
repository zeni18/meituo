## 三、从最新规范与恢复原稿得到的设计理解

来源：`docs/merchant-ui-v2.md`，以及恢复的工作台、AI 商品图、素材库 HTML 原稿。

- 统一浅色视觉体系：浅灰背景、白色内容面、黑灰文字；靛紫用于 AI 生成、当前导航、图表主序列、焦点和选中状态。常规上传、管理动作使用近黑或白色按钮。
- 作品是视觉中心。图片、视频应有足够展示空间，控制区保持清楚、紧凑，避免说明文字和装饰抢占主内容。
- 保留规范允许的层次感：柔和投影、渐隐面积图、受控的渐变与堆叠卡片。不能把“克制用色”理解成删掉所有精细视觉效果。
- 字体、间距、圆角、控件高度和图标应全站一致；不用浅色底框包线性图标，不用满页彩色状态标签。
- 先落实结构和操作层级，再核对视觉细节。仅换颜色不能算完成 UI v2。
- 账户单位统一 TP；原稿旧“算力、点”文案保留在参考文件中供溯源，业务页面遵循最新规范。

## 四、四项改造的验收重点

| 范围 | 应落实的结果 | 应保留的业务能力 |
|---|---|---|
| 素材库 | 标题及右侧主操作；下划线类型页签；文件夹与素材列表清楚分区；统一筛选、网格、分页；多选后深色批量操作条 | 真实分类、上传、搜索、文件夹、标签、预览、批处理及归属约束 |
| 作品库 | 与素材库采用统一列表骨架，突出作品展示；各内容类型与原生筛选衔接清楚 | 原作品、成片、图文等数据来源；筛选、收藏、下载和原有生成归库关系 |
| 视频剪辑 | 按最新编辑器规范组织素材、编辑区和预览设置；操作优先级清楚，避免重复主按钮 | 现有模式、素材选择与上传、字幕声音设置、工程、编排、预览和云合成流程 |
| 共用弹窗 | 统一标题、内容、选择状态、取消与确认位置，以及窄屏和长内容表现 | 素材选择、企业知识库和 TP 确认的实际数据与操作语义 |

数量、状态、消耗不能用参考稿示例数字冒充真实数据；没有真实费用报价的操作不能为迎合设计稿显示虚构 TP。
